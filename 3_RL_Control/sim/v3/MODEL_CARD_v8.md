# 모델 카드 — SAC 잔차 정책 v8

> Raspberry Pi 5 + BeamNG.drive(Collector 입력) + STM32 OASIS_FALLBACK v2 구성에 배포하는 최종 볼스터 제어 정책의 요약입니다.
> 구성, 설계 요점, 검증, 결과, 한계를 한 장에 정리했습니다. 상세 사양은 [`deploy/CONTROL_SPEC.md`](../../deploy/CONTROL_SPEC.md)를 봅니다.

## 설계 요점

| # | 항목 | 내용 | 설계 근거 |
|---|---|---|---|
| 1 | **보드 구동기 모델** | OASIS_FALLBACK v2 펌웨어 쌍둥이(`fb_a2_step`): 서보당 2 µs / 20 ms, STM 튜닝 속도 {10, 20} °/s, yaw 상한 {15, 20}°, CAD 결합 한계. 0 → 9°에 1.52 s (감사 6b) | 실제 구동기는 더 빠른 구동기를 가정한 이전 모델보다 3–5배 느립니다. 이전 정책(v7)을 이 구동기에서 평가하면 규칙보다 나빴습니다(같은 에피소드 차 −5.8) |
| 2 | **Collector 입력** | 앞 도로 정보 없음, 요레이트 = a_y / max(v, 5). 예측기와 정책 모두 이 입력으로 학습 (`beamng_drive_collector.yaml`) | BeamNG.drive + Collector v0.3이 제공하는 신호만 사용. 1초 예측 오차 0.090 g (현재 값 유지 0.140, 핸들만 0.134, 도로 정보가 있으면 0.069) |
| 3 | **튜닝 규칙** | gain 16, 0.7초 앞. 검증 J 5.38 | 구동기가 느려 목표가 빨리 커지는 높은 gain이 유리 (gain 8은 5.21) |
| 4 | **보상 = 평가 점수** (`reward_score.yaml`, `env_v3 reward.mode: score`) | 쌍둥이 대비 CoM 감소율, 20 N 초과 시간, 과압박을 평가 점수와 같은 가중으로 스텝마다 분배. 평가 점수와 순서 일치 88 % (감사 10번) | 이전 보상은 규칙을 볼스터 열림보다 낮게 평가했고(−21.8 vs −0.3, 순서 일치 35 %, `results/v8/reward_diag.json`), 그 보상으로 학습한 정책(`v8a`)은 규칙보다 나빴습니다(−5.5, −7.1) |
| 5 | **규칙에서 출발하는 SAC** | 처음 20k 스텝은 critic만 학습(`--actor_delay 20000`), 작은 초기 탐색(`--init_log_std −1`, 워밍업 잡음 0.1), 보정 폭 ±0.25, 보정 크기 벌점 0.02 | 근거가 약한 곳에서는 규칙에 머무르게 함 |
| 6 | **선택** | 규칙 튜닝과 같은 검증 48 에피소드(시드 3000+, 레벨 1·2)의 J로 체크포인트와 실행을 고름. 규칙 자신도 후보로 채점 | 평가 은행은 결과 보고에만 사용 |
| 7 | **GPU 학습** | 4 시드 동시 (RTX 4070 SUPER, 시드당 약 19 ms/스텝, 200k 스텝 약 1시간) | 체크포인트는 CPU 텐서로 저장되므로 Pi·export 경로는 그대로 |
| 8 | **Pi 런타임** | `oasis_rt.app`이 백업 제어기의 `BoardLink`(OASIS_FALLBACK v2)와 `VehicleValidator`를 그대로 사용 | 모델이 다른 구동기용이거나 STM 튜닝이 학습 범위보다 느리면 규칙으로 세션 진행 |

## 결과 요약

평가 은행 48 에피소드, 같은 에피소드 비교 (`results/v8/eval_unified.json`).

| 제어기 | J | 규칙 대비 평균 차 [95 % CI] | 중앙값 차 | 이긴 에피소드 |
|---|---|---|---|---|
| **RL `v8_s1` (배포)** | **3.92** | −0.95 [−3.06, +0.73] | +0.02 | 32 / 48 |
| 튜닝 규칙 (hot fallback) | 3.93 | — | — | — |
| FB V6 (cold fallback) | 1.70 | −2.34 [−6.81, +2.10] | −1.50 | 10 / 48 |
| 참고: 이전 정책 `v7_s1` | 3.15 | −5.82 [−17.2, +2.44] | −0.06 | 20 / 48 |
| 참고: 이전 보상 `v8a_s1` | 2.10 | −5.49 [−12.3, −0.30] | −0.27 | 10 / 48 |

- **RL과 규칙은 같은 수준입니다.** 32 / 48 에피소드에서 우세, 중앙값 차 +0.02, Wilcoxon p = 0.28.
  - 평균 차 −0.95는 대부분 에피소드 하나(1015 L0)에서 나옵니다. 이를 빼면 −0.13입니다.
- **RL이 자기 fallback보다 나쁜 문제는 해소됐습니다.** 이전 정책(−5.8)과 이전 보상 정책(−5.5, −7.1)은 규칙보다 분명히 나빴습니다.
- **규칙보다 분명히 낫지는 않습니다.** 데이터 한계(줄일 흔들림이 작음, 권한 간접 추정, 느린 구동기) 안에서는 규칙이 이미 대부분의 이득을 냅니다.
- **시드 차이가 큽니다.**
  - 4 시드 모두 검증 J는 규칙보다 높았습니다(5.74–5.93 vs 5.38).
  - 평가 은행에서는 `s0`, `s2`가 꼬리 에피소드에서 크게 잃었습니다(J 2.97, 2.29).
  - `v8_s1`만 두 평가 모두에서 규칙 이상입니다.
- 성능은 a_y 미리보기에서 나옵니다(관측 제거 −8.6). 압력·자세·체형 단서는 거의 쓰지 않습니다.
- RL이 규칙보다 나은 체형은 없습니다(A −0.6, B −0.6, 넓은 체형 −4.7, 모두 유의하지 않음).
- FB V6보다는 분명히 낫습니다(J 3.9 vs 1.7, FB V6가 나은 에피소드 10 / 48).

## 한계

| 항목 | 내용 |
|---|---|
| 실물 검증 범위 | 실물 착석 시험은 G 기본 곡선 + 정책 보정(±1.5°) 법칙으로 수행했습니다. 정책 단독(`control.mode: rl`)의 성능 수치는 시뮬레이터와 모의 보드 SIL 결과입니다 |
| 정지 벤치 | 관성이 재현되지 않습니다. 벤치에서 보이는 것은 추종·지연·안전·체감이며, CoM 감소의 근거는 시뮬레이터입니다 |
| 요레이트 추정 | a_y / v는 정상 원선회에서만 정확합니다. 학습과 배포는 같은 추정을 보지만, 실제 과도 구간의 오차는 실제 로그로 확인해야 합니다 |
| 예측기 이득 | 차선 변경·슬라럼 이득 일부는 합성 기동 모양에서 나옵니다. Collector 원본 주행 로그로 다시 검증해야 합니다 |
| 조임 → 압력 | "조이면 같은 쪽 압력이 오른다"는 접촉 데이터로 직접 확인되지 않았습니다. 권한은 실차 1회와 벤치 2명의 압력 비, 기하로 간접 추정했습니다 |
| 인터락 임계값 | 60 / 120 N은 벤치에서 다시 보정해야 합니다. 압력 → 힘 변환이 FSR 역모델 추정이기 때문입니다([저울 보정 절차](../../deploy/tools/PAD_CALIB_PROTOCOL.md)) |
| 선택 기준 | 10 % 절사평균이라 꼬리 위험이 보이지 않습니다. p10이나 같은 에피소드 차의 평균을 함께 보는 것이 향후 개선점입니다 |
| 운용 권장 | 벤치 주관 평가에서 RL의 체감이 규칙보다 나쁘면 `control.mode: rule`을 권합니다. 시뮬레이터 성능은 같습니다 |

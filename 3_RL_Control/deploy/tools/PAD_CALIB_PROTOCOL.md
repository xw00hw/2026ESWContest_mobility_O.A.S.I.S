# 측면 패드 저울 캘리브레이션 절차 (약 30–40분)

목적은 측면 패드 2개(우 `A1_C1`, 좌 `A1_C3`)의 **counts/N**을 실측하는 것입니다.
이 값을 측정하면 세 가지가 해결됩니다.

1. 런타임 인터락(60 N soft, 120 N hard)이 실제 N 단위로 동작합니다. 지금은 모델값 32.6 counts/N을 씁니다.
2. 실차 게인(7234 counts/g)을 N/g로 환산할 수 있게 되어, 지금까지 식별할 수 없었던 접촉 강성 k가 식별됩니다 (`calib_v2.py --pad_calib`).
3. 벤치 조임 효과 15.7 counts/°를 **N/°**로 환산합니다. 모델값은 0.48 N/°입니다.

부수적으로 **채널 매핑도 확인**합니다. 우측 패드를 눌렀을 때 A1_C1이 가장 크게 반응해야 합니다.

## 준비물

- 디지털 저울. 최소 0–12 kg, 0.05 kg 이상 분해능. 주방 저울이나 소형 플랫폼 저울을 씁니다.
- **누름판(puck):** 약 8×8 cm 단단한 판에 5 mm 폼을 붙인 것. 몸통 접촉을 흉내 내기 위한 것이고, 모든 측정에 같은 것을 씁니다.
- 패드 중심 표시용 마스킹테이프와 펜.
- Pi + STM32 연결 상태. 볼스터는 **열린 상태(yaw 0)**, 시트에는 사람이 앉지 않습니다.

## 누르는 방법

1. 패드 중심을 테이프로 표시하고, 누름판 중심을 거기에 맞춥니다.
2. 저울을 **누름판과 손 사이**에 둡니다. 누르는 방향과 같은 자세(옆으로 세운 상태)에서 **영점(tare)** 을 잡은 뒤 저울 바닥면으로 누름판을 밉니다.
   패드면에 수직으로 누릅니다. 비스듬히 누르면 측정값이 실제보다 작게 나옵니다.
3. 숫자가 안정되면(±0.1 kg) 그 상태를 1–2초 유지하고 Enter를 누릅니다. 최근 1.5 s를 캡처합니다.
   손을 뗀 다음 저울 값(kg)을 입력합니다.
4. 단계: **0 → 10 → 20 → 40 → 60 → 80 → 100 N → 80 → … → 0** (1 kg ≈ 9.8 N). 화면이 목표 kg을 알려 줍니다. 정확히 맞출 필요는 없고 **실제로 읽은 값**을 입력하면 됩니다.
   올라가는 구간과 내려가는 구간을 모두 측정하는 이유는 히스테리시스를 재기 위해서입니다. 내려갈 때는 힘을 **천천히** 줄입니다.

## 순서

```bash
cd deploy
# 1) 우측 패드, 2회 반복 (세션이 다르면 영점 드리프트가 따로 보정됨)
python tools/pad_calib.py record --pad side_R --out pad_runs/R_y0.csv
python tools/pad_calib.py record --pad side_R --out pad_runs/R_y0.csv
# 2) 좌측 패드, 2회
python tools/pad_calib.py record --pad side_L --out pad_runs/L_y0.csv
python tools/pad_calib.py record --pad side_L --out pad_runs/L_y0.csv
# 3) (선택) 배치 민감도: 중심에서 2 cm 위/아래
python tools/pad_calib.py record --pad side_R --placement up2cm --out pad_runs/R_y0_up.csv
# 4) (선택) 볼스터 각도 영향: STM32를 ARM하고 양쪽을 10°로 유지한 채 측정
python tools/pad_calib.py record --pad side_R --yaw 10 --out pad_runs/R_y10.csv
# 5) 피팅
python tools/pad_calib.py fit pad_runs/*.csv --out model/pad_calib.json
```

`--yaw`를 주면 볼스터가 실제로 움직입니다. 손과 누름판이 기구에 끼지 않게 하고, 저출력 시험 규칙을 따릅니다.
- 기본 펌웨어는 OASIS_FALLBACK v2(`--firmware fallback_v2`)입니다. 이전 수집 펌웨어는 `--firmware control_v6`로 고릅니다.
- v2에서 `--yaw`를 주면 다음 순서로 진행합니다. 도구가 lease를 갱신하는 동안, 벤치의 운영자가 감독자입니다.
  1. PWM OFF를 확인합니다.
  2. FB_ARM을 보냅니다. 이때 벤치 영점 펄스가 바로 나갑니다.
  3. STM 튜닝 속도로 목표 yaw까지 이동합니다. 목표는 STM yaw 상한과 CAD 안으로 제한됩니다.
- Ctrl-C를 누르면 FB_OFF를 보내고 OFF를 확인합니다.

## 결과 확인 (`model/pad_calib.json`)

| 항목 | 기준 |
|---|---|
| `mapping_check.*.ok` | 모두 `true`. 아니면 `config.yaml`의 `pressure.channels`와 `calib_v2.py`의 FEATS를 고쳐야 함 |
| `r2_linear` (0–80 N) | ≥ 0.95. 낮으면 누름이 불안정했거나 FSR이 포화된 것. `saturating_fit` 참고 |
| `slope_cv` (세션 간) | ≤ 10 %. 크면 누름 위치나 각도가 흔들린 것이니 다시 측정 |
| `hysteresis_N` | 기록만 함. 벤치에서 85 counts ≈ 2.6 N(모델 G 기준)이 관측됨 |
| `derived.vs_model_G` | 1.0이면 지금까지의 모델이 맞음. 0.5–2 범위를 벗어나면 DR 범위도 다시 잡아야 함 |

## 이후 처리

- 런타임: `config.yaml`의 `pressure.pad_calib`가 이 파일을 가리키면 자동으로 counts/N을 대체합니다.
- 모델 재구축: `python pipeline/rebuild.py --version v3 --pad_calib deploy/model/pad_calib.json`.
  calib_v2가 k를 식별하고, DR 범위를 좁힌 뒤 재학습합니다.
- 합성 데이터로 피팅 자체를 시험하려면: `python tools/pad_calib.py demo --out pad_runs/demo.csv`.
  demo처럼 G가 15.6이면 k ≈ 21 kN/m로 식별되어 현재 DR 범위(1–10 kN/m)를 벗어납니다. 파이프라인 게이트가 이런 경우를 잡아냅니다.
  권한 비율(0.043 g 등가)은 데이터 두 개의 비로 정해지므로 G가 달라져도 바뀌지 않습니다. 바뀌는 것은 절대 힘, 즉 인터락과 편안함 지표입니다.

## 부록 A — 전압 기준과 10/26 저울 곡선 (`fsr_curve.py`, `fsr_curve_20261026.json`)

**STM32 쪽 기준 (NUCLEO-H723ZG):**
- ADC1은 12bit(0–4095)이고, 오프셋·선형성 보정을 쓴다.
- 펌웨어에 VREFBUF 설정이 없고 VREFINT도 읽지 않는다. 따라서 ADC 상한은 보드의 VREF+ 핀이다. Nucleo-144 기본 배선에서 VREF+는 VDDA, 즉 3.3 V 레일이다(UM2407에서 확인 권장).
- MUX와 센서는 같은 3V3 레일(CN8-7)에서 전원을 받는다.
- 그러므로 **카운트 = 4095 × 분압비**다. 레일이 3.28 V든 3.32 V든 힘 환산에는 영향이 없다.
- 정확한 VREF+ 값은 카운트를 볼트로 표시할 때(`raw × 3.3 / 4095`)만 필요하다. 확인하려면 3V3–GND 전압을 멀티미터로 재거나, 펌웨어에서 VREFINT를 읽어 공장 보정값과 비교한다.

**우노 표 → STM 카운트:**
- 우노는 5 V 전원에 5 V 기준이다. 표의 전압은 정확히 10bit 코드 250, 300, … 470에 해당한다.
- 같은 분압 회로라면 STM 카운트 = 4095 × V/5이다. 그러면 1001 → 1881 카운트, 3.3 V 표시로는 0.81 → 1.52 V가 된다.
- 접촉 지름 3.15 cm(7.79 cm²)에서 힘은 4.3 → 529 N이다.
- 곡선식은 `counts = 1919 F^0.84 / (F^0.84 + 3.99^0.84)`이고, 최대 잔차는 12카운트다.

| 힘 [N] | 4.3 | 9.4 | 17.5 | 27 | 38 | 68 | 102 | 181 | 529 |
|---|---|---|---|---|---|---|---|---|---|
| STM 카운트 | 1001 | 1281 | 1481 | 1601 | 1681 | 1762 | 1801 | 1841 | 1881 |
| 국소 게인 [counts/N] | 91 | 39 | 17 | 8 | 4.2 | 1.7 | 0.9 | 0.4 | 0.1 |

**확인이 필요한 점 — 분압 회로가 같은가?**
- 실차에서 A1_C1은 최대 **2316**, A1_C3은 **2063** 카운트까지 읽혔다. 이 곡선의 포화(약 1880–1920)보다 높다.
- 그러므로 **A1 뱅크의 분압 저항 R_m은 우노 시험과 다르다.** 팀 문서에도 A1/A2 저항은 미확인으로 되어 있다.
- 두 저항값을 알면 아래처럼 다시 환산한다. 실차 최대값만 보면 저항 비는 1.5 이상으로 추정된다.
  ```
  python fsr_curve.py --rm_uno <우노 R_m> --rm_stm <A1 R_m> --write
  ```
- 같은 1456카운트라도 저항 비가 1.0이면 15.6 N, 1.5이면 5.7 N이다. 저항값이 확정되기 전에는 이 곡선의 N 값을 쓰지 않는다.

**런타임에 주는 영향:**
- 지금 인터락은 선형 게인(v2 32.6, v3 86.9 counts/N)을 쓴다. 이 게인으로는 "휴지 + 60 N"이 휴지 + 1,956카운트 이상이 되므로, 포화하는 실제 패드에서는 **인터락이 걸리지 않는다.**
- 그래서 시작할 때 패드별로 인터락이 실제로 작동하는 카운트를 로그로 남긴다.
- 단위와 상관없는 보호로 `safety.pad_saturation_counts`를 둔다. 볼스터가 닫힌 쪽의 패드가 이 값 이상이면 그쪽을 해제한다.
  - 모의 시험에서는 우측 하중 0.3 g 조건에서 가드 2200을 켜자, 닫힘 시간이 92 %에서 0 %가 됐다.
- 곡선을 다시 환산한 뒤에는 `pressure.fsr_curve`를 켜서 비선형 힘 계산으로 바꾼다.

# 측면 패드 저울 보정 절차

> 측면 패드 2개(우 `A1_C1`, 좌 `A1_C3`)의 **counts/N**을 저울로 실측하는 절차입니다(소요 약 30–40분).
> 결과 파일 `pad_calib.json`은 런타임 인터락과 시뮬레이터 보정(`calib_v2.py`)이 함께 읽습니다.

---

## 목적

이 값을 측정하면 세 가지가 해결됩니다.

| # | 효과 | 측정 전 |
|---|---|---|
| 1 | 런타임 인터락(60 N soft, 120 N hard)이 실제 N 단위로 동작 | 시뮬레이터 모델값 32.6 counts/N 사용 |
| 2 | 실차 측면 이득(7,234 counts/g)을 N/g로 환산 → 접촉 강성 k 식별 (`calib_v2.py --pad_calib`) | k를 식별할 수 없음 |
| 3 | 벤치 조임 효과 15.7 counts/°를 **N/°**로 환산 | 모델값 0.48 N/° |

부수적으로 **채널 매핑도 확인**합니다. 우측 패드를 눌렀을 때 `A1_C1`이 가장 크게 반응해야 합니다.

---

## 준비물

- **디지털 저울:** 최소 0–12 kg, 분해능 0.05 kg 이상 (주방 저울이나 소형 플랫폼 저울).
- **누름판(puck):** 약 8 × 8 cm 단단한 판에 5 mm 폼을 붙인 것. 몸통 접촉을 흉내 내며, 모든 측정에 같은 것을 씁니다.
- 패드 중심 표시용 마스킹테이프와 펜.
- Pi + STM32 연결 상태. 볼스터는 **열린 상태(yaw 0)**, 시트에는 사람이 앉지 않습니다.

---

## 누르는 방법

1. 패드 중심을 테이프로 표시하고, 누름판 중심을 거기에 맞춥니다.
2. 저울을 **누름판과 손 사이**에 둡니다. 누르는 방향과 같은 자세(옆으로 세운 상태)에서 **영점(tare)** 을 잡은 뒤, 저울 바닥면으로 누름판을 밉니다.
   - 패드면에 수직으로 누릅니다. 비스듬히 누르면 측정값이 실제보다 작게 나옵니다.
3. 숫자가 안정되면(±0.1 kg) 1–2초 유지하고 Enter를 누릅니다. 도구가 최근 1.5 s를 캡처합니다. 손을 뗀 뒤 저울 값(kg)을 입력합니다.
4. 단계: **0 → 10 → 20 → 40 → 60 → 80 → 100 N → 80 → … → 0** (1 kg ≈ 9.8 N).
   - 화면이 목표 kg을 알려 줍니다. 정확히 맞출 필요는 없고 **실제로 읽은 값**을 입력하면 됩니다.
   - 올라가는 구간과 내려가는 구간을 모두 재는 것은 히스테리시스를 측정하기 위해서입니다. 내려갈 때는 힘을 **천천히** 줄입니다.

## 실행 순서

```bash
cd deploy
# 1) 우측 패드, 2회 반복 (세션별 영점 드리프트는 따로 보정됨)
python tools/pad_calib.py record --pad side_R --out pad_runs/R_y0.csv
python tools/pad_calib.py record --pad side_R --out pad_runs/R_y0.csv
# 2) 좌측 패드, 2회
python tools/pad_calib.py record --pad side_L --out pad_runs/L_y0.csv
python tools/pad_calib.py record --pad side_L --out pad_runs/L_y0.csv
# 3) (선택) 배치 민감도: 중심에서 2 cm 위/아래
python tools/pad_calib.py record --pad side_R --placement up2cm --out pad_runs/R_y0_up.csv
# 4) (선택) 볼스터 각도 영향: STM32를 ARM하고 양쪽을 10°로 유지한 채 측정
python tools/pad_calib.py record --pad side_R --yaw 10 --out pad_runs/R_y10.csv
# 5) 피팅
python tools/pad_calib.py fit pad_runs/*.csv --out model/pad_calib.json
```

**`--yaw` 사용 시 주의** — 볼스터가 실제로 움직입니다. 손과 누름판이 기구에 끼지 않게 하고 저출력 시험 규칙을 따릅니다.

| 항목 | 내용 |
|---|---|
| 펌웨어 | 기본 OASIS_FALLBACK v2 (`--firmware fallback_v2`). 이전 수집 펌웨어는 `--firmware control_v6` |
| 동작 순서 (v2) | ① PWM OFF 확인 → ② FB_ARM 전송 (벤치 영점 펄스가 바로 나감) → ③ STM 튜닝 속도로 목표 yaw까지 이동 (STM yaw 상한과 CAD 한계 안으로 제한) |
| 감독 | 도구가 lease를 갱신하는 동안 벤치 운영자가 감독자 역할 |
| 정지 | Ctrl-C → FB_OFF 전송 후 OFF 확인 |

## 결과 확인 (`deploy/model/pad_calib.json`)

| 항목 | 기준 |
|---|---|
| `mapping_check.*.ok` | 모두 `true`. 아니면 `config.yaml`의 `pressure.channels`와 `sim/v2/calib_v2.py`의 `FEATS`를 고쳐야 함 |
| `r2_linear` (0–80 N) | ≥ 0.95. 낮으면 누름이 불안정했거나 FSR이 포화된 것 (`saturating_fit` 참고) |
| `slope_cv` (세션 간) | ≤ 10 %. 크면 누름 위치나 각도가 흔들린 것이므로 다시 측정 |
| `hysteresis_N` | 기록만 함. 벤치에서 85 counts ≈ 2.6 N(모델 G 기준) 관측 |
| `derived.vs_model_G` | 1.0이면 기존 모델이 맞음. 0.5–2 범위를 벗어나면 도메인 랜덤화 범위도 다시 잡아야 함 |

## 이후 처리

- **런타임:** `config.yaml`의 `pressure.pad_calib`(기본 `../model/pad_calib.json`)가 이 파일을 가리키면 자동으로 counts/N을 대체합니다.
- **시뮬레이터 재보정:** `python sim/v2/calib_v2.py --pad_calib deploy/model/pad_calib.json`으로 접촉 강성 k를 식별하고, 좁혀진 범위로 학습 파이프라인(`sim/v3/final/run_final.sh`)을 다시 실행합니다.
- **피팅 자체 시험:** `python tools/pad_calib.py demo --out pad_runs/demo.csv`로 합성 데이터를 만듭니다.
  - demo처럼 G가 15.6이면 k ≈ 21 kN/m로 식별되어 현재 범위(1–10 kN/m)를 벗어납니다. 파이프라인 게이트가 이런 경우를 잡아냅니다.
  - 권한 비율(0.043 g 등가)은 두 데이터의 비로 정해지므로 G가 달라져도 바뀌지 않습니다. 바뀌는 것은 절대 힘, 즉 인터락과 편안함 지표입니다.

## 부록 A — 전압 기준과 FSR 저울 곡선 (`fsr_curve.py`, `fsr_curve.json`)

### STM32 쪽 기준 (NUCLEO-H723ZG)

- ADC1은 12 bit(0–4095)이고 오프셋·선형성 보정을 씁니다.
- 펌웨어에 VREFBUF 설정이 없고 VREFINT도 읽지 않습니다. 따라서 ADC 상한은 보드의 VREF+ 핀이며, Nucleo-144 기본 배선에서 VREF+는 VDDA(3.3 V 레일)입니다(UM2407에서 확인 권장).
- MUX와 센서는 같은 3V3 레일(CN8-7)에서 전원을 받습니다.
- 그러므로 **카운트 = 4095 × 분압비**입니다. 레일이 3.28 V든 3.32 V든 힘 환산에는 영향이 없습니다.
- 정확한 VREF+ 값은 카운트를 볼트로 표시할 때(`raw × 3.3 / 4095`)만 필요합니다. 확인하려면 3V3–GND 전압을 멀티미터로 재거나, 펌웨어에서 VREFINT를 읽어 공장 보정값과 비교합니다.

### 아두이노 우노 저울 시험 → STM 카운트

- 우노는 5 V 전원, 5 V 기준입니다. 표의 전압은 정확히 10 bit 코드 250, 300, … 470에 해당합니다.
- 같은 분압 회로라면 STM 카운트 = 4095 × V/5입니다. 이 경우 1001 → 1881 카운트, 3.3 V 표시로는 0.81 → 1.52 V가 됩니다.
- 접촉 지름 3.15 cm(7.79 cm²)에서 힘은 4.3 → 529 N입니다.
- 곡선식은 `counts = 1919 F^0.84 / (F^0.84 + 3.99^0.84)`이고, 최대 잔차는 12카운트입니다.

| 힘 [N] | 4.3 | 9.4 | 17.5 | 27 | 38 | 68 | 102 | 181 | 529 |
|---|---|---|---|---|---|---|---|---|---|
| STM 카운트 | 1001 | 1281 | 1481 | 1601 | 1681 | 1762 | 1801 | 1841 | 1881 |
| 국소 게인 [counts/N] | 91 | 39 | 17 | 8 | 4.2 | 1.7 | 0.9 | 0.4 | 0.1 |

### 확인 필요: 분압 회로가 같은가

- 실차 주행에서 `A1_C1`은 최대 **2316**, `A1_C3`은 **2063** 카운트까지 읽혔습니다. 이 곡선의 포화(약 1880–1920)보다 높습니다.
- 따라서 **A1 뱅크의 분압 저항 R_m은 우노 시험과 다릅니다.** A1/A2 뱅크의 분압 저항값은 아직 확인되지 않았습니다.
- 두 저항값을 알면 아래처럼 다시 환산합니다. 실차 최대값만 보면 저항 비는 1.5 이상으로 추정됩니다.
  ```bash
  python fsr_curve.py --rm_uno <우노 R_m> --rm_stm <A1 R_m> --write
  ```
- 같은 1456카운트라도 저항 비가 1.0이면 15.6 N, 1.5이면 5.7 N입니다. **저항값이 확정되기 전에는 이 곡선의 N 값을 쓰지 않습니다**(`pressure.fsr_curve: null`).

### 런타임에 주는 영향

- 현재 인터락은 선형 게인(v2 모델 32.6, v3 모델 86.9 counts/N)을 씁니다. 이 게인으로는 "휴지 + 60 N"이 휴지 + 1,956카운트 이상이 되므로, 포화하는 실제 패드에서는 **인터락이 걸리지 않습니다.**
- 그래서 시작할 때 패드별로 인터락이 실제로 작동하는 카운트를 로그로 남깁니다.
- 단위와 무관한 보호로 `safety.pad_saturation_counts`를 둡니다. 볼스터가 닫힌 쪽의 패드가 이 값 이상이면 그쪽을 해제합니다.
  - 모의 시험에서 우측 하중 0.3 g 조건에 가드 2200을 켜자 닫힘 시간이 92 %에서 0 %가 됐습니다.
- 곡선을 다시 환산한 뒤에는 `pressure.fsr_curve`를 켜서 비선형 힘 계산으로 바꿉니다.

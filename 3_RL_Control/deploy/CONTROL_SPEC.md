Pi(`oasis_rt.app`)에서 세 제어기 중 하나가 돕니다. BeamNG 입력, 보드 링크, 안전 계층은 셋이 같습니다.

| | **RL 정책 (기본)** | **튜닝 규칙 (hot fallback)** | **FB V6 (cold fallback)** |
|---|---|---|---|
| 무엇 | 규칙 + SAC 잔차 신경망 | 규칙만 (RL의 prior) | BeamNG_Bolster_FB Experiment A 제어기, 코드 그대로 (main: V7 코드 = V6 제어 법칙 + 큰 a_y 포화 + 충격 OFF) |
| 선택 | `control.mode: rl` | `control.mode: rule`, 액터 실패 시 자동 (세션 끝까지) | `control.mode: fb_v6`, 모델 패키지가 없을 때 자동 |
| 입력 | BeamNG 1 s 예측기, 압력, 보고 각도, 체형 | 같음 (예측기 0.7 s 앞) | 실제 a_y(0.15 s LPF), 조향 2° 선제 신호. 압력·체형 없음 |
| 계산 | 513 → 256 → 256 → 2 MLP (C / numpy) | 비교 1번, 곱 1번 | FB 상태기계 (50 Hz) |
| 학습 / 튜닝 | 시뮬레이터 v8 (A v2 구동기), 규칙에서 시작해 ±0.25 조정, 보상 = 평가 점수, 200k 스텝 × 4 시드 | 같은 시뮬레이터, 72개 격자 | FB 결정 (ADR-020–032), STM 튜닝값 사용 |

## 2. 출력: 행동 → 볼스터 목표각

행동 `a = [c, d]`, 각각 [−1, 1]. 두 제어기가 같은 변환을 씁니다(`obs_layout.action_to_targets`).

```
c' = (c + 1)/2 · θmax/2          d' = d · θmax/2          θmax = 20°
yaw_L = clip(c' + d', 0, 20°)     yaw_R = clip(c' − d', 0, 20°)     pitch_L = pitch_R = 0   (yaw 전용 모델)
```

- c = −1, d = 0이면 양쪽이 열립니다(0°).
- d < 0이면 오른쪽이 조입니다. 왼쪽으로 돌 때(a_y > 0) 몸이 오른쪽으로 밀리므로, 그쪽을 받칩니다.

## 3. a_y 미리보기: BeamNG 1 s 예측기 (`oasis_rt/predictor.py BeamNGPredictor`)

BeamNG에서 얻을 수 있는 신호를 합칩니다. 학습(시뮬레이터)과 Pi가 같은 클래스와 같은 가중치 파일을 씁니다(`model_v8/predictor.npz`). 구동기는 미리보기에 들어가지 않습니다.

**이 통합(BeamNG.drive + Collector)에서는 앞 도로 정보와 요레이트가 없습니다.** 그래서 v8 예측기는 그 입력(`road_valid` 0, 요레이트 = a_y / max(v, 5))으로만 다시 학습했습니다. 도로 미리보기(BeamNG.tech + BeamNGpy 브리지)와 v7 예측기는 `feat/rl-final-beamng`에 있습니다.

| 입력 (31개, 20 Hz) | 출처 |
|---|---|
| 핸들 사전 예측 a_y(h) 10개 | `WheelPreviewPredictor`: 핸들 각 + 조향 속도 외삽(Ts 0.3 s) → 정상상태 a_y → 요 지연 0.12 s. 공칭 BeamNG 차(L 2.7 m, 조향비 15) |
| 앞 도로 a_y(h) = v² κ(s + v h) / g, 10개 + 유효 플래그 | BeamNG.tech 브리지 `RoadPreview`. BeamNG.drive / Collector에는 없음 → 0 (v8 학습도 0) |
| 현재 a_y, a_x, 요레이트, 속도, 핸들 각·속도, 0.1–0.4 s 전 a_y | Collector 행 (요레이트는 a_y / max(v, 5) 추정, 시뮬레이터도 같은 식) |

- 출력은 **핸들 사전 예측 + MLP 잔차**(31 → 64 → 64 → 10)입니다. 가중치가 없으면 핸들 사전 예측과 같습니다.
- 학습 데이터: 최종 시뮬레이터 v8 1,200 에피소드(93만 스텝, 시드 20000+), 검증 240 에피소드(18.7만 스텝, 시드 21000+). 행 주기 25–60 Hz(Collector).

검증 RMS [g] (`results/v8/predictor_eval.json`, 모두 도로 없음):

| 앞 시간 | 0.1 s | 0.3 s | 0.5 s | 0.7 s | 1.0 s |
|---|---|---|---|---|---|
| **BeamNG 예측기 v8** | 0.023 | 0.038 | 0.054 | 0.070 | **0.090** |
| 핸들 사전 예측만 | 0.033 | 0.056 | 0.078 | 0.101 | 0.134 |
| 미리보기 없음 (hold) | 0.034 | 0.063 | 0.088 | 0.112 | 0.140 |
| 참고: v7 예측기, 도로 있음 (BeamNG.tech) | 0.023 | 0.035 | 0.046 | 0.056 | 0.069 |

- 1 s 앞 오차가 hold의 64 %입니다. 도로 정보가 있던 v7(0.069)보다 나쁩니다.
- 기동별 1 s 오차 (예측기 / hold): 차선 변경 0.104 / 0.185, 슬라럼 0.100 / 0.217, 도심 회전 0.127 / 0.147, 무작위 조향 0.091 / 0.096.
  - 예측할 근거가 없는 무작위 조향에서는 hold와 같습니다. 억지로 예측하지 않습니다.
- **한계:** 차선 변경과 슬라럼의 이득에는 합성 기동 모양을 배운 몫이 섞여 있습니다. 실제 BeamNG 주행 로그(Collector 원본)로 다시 검증해야 합니다.
- 요레이트 추정(a_y / v)은 정상 원선회에서만 맞습니다. 시뮬레이터도 같은 추정을 쓰므로 학습과 배포는 같은 입력을 봅니다. 하지만 실제 차량의 과도 구간에서 실제 요레이트와 얼마나 다른지는 실제 로그로 확인해야 합니다.

## 4. 튜닝 규칙 (fallback 제어)

```
ay = ay_pred[0.7 s]                          관측 6번 = BeamNG 예측기의 0.7 s 앞
m  = max(|ay| − deadband, 0)                 deadband = 0
c  = −1                                      공통 조임 없음
d  = clip(−gain · sign(ay) · m, −1, 1)       gain = 16 /g
```

- 실제 각도로 풀면 **밀릴 쪽 볼스터 = min(10°, 160°/g × |a_y(0.7 s)|)**, 반대쪽은 0°입니다.
- 0.063 g에서 10°에 도달합니다. 보드 구동기가 yaw 약 5–6 °/s로 느리기 때문에, 목표가 빨리 커지는 높은 gain이 유리합니다(v7은 12).

**튜닝 절차** (`sim/v3/tune_rule.py --grid`, 결과 `results/v8/rule.json`)

- 격자는 gain {6, 8, 10, 12, 14, 16} × 미리보기 {0.3, 0.4, 0.5, 0.7, 0.9, 1.0 s} × deadband {0, 0.02 g}, 72개입니다.
  - 구동기가 느려 미리보기를 1.0 s까지 넓혔습니다(v7: gain 4–14, 0.1–0.7 s).
  - 채택된 gain 16은 격자 끝입니다. 더 높으면 사실상 on/off 동작이라 더 넓히지 않았습니다.
- 점수(에피소드마다, 높을수록 좋음)는 다음과 같습니다.
  - CoM RMS 감소율 [%]
  - − 0.5 × "볼스터가 더한 압박 > 20 N"인 시간 [%]
  - − 100 × 평균((추가 압박 − 20)/20)²
- J는 튜닝 시드 2000+ 48개(레벨 1·2)에 대한 10 % 절사평균입니다.
- 튜닝 상위 5개를 **검증 시드 3000+ 48개**로 다시 점수 매겨, 검증 J가 가장 높은 것을 골랐습니다(v4의 DE는 튜닝 시드에 과적합했습니다).

| 후보 | 튜닝 J | 검증 J | 검증 CoM 감소 | 20 N 초과 시간 |
|---|---|---|---|---|
| **gain 16, 0.7 s (채택)** | 4.47 | **5.38** | 10.3 % | 6.7 % |
| gain 16, 0.9 s | 4.29 | 5.37 | 10.3 % | 6.7 % |
| gain 14, 0.7 s | 4.35 | 5.31 | 10.1 % | 6.5 % |
| gain 14, 0.9 s | 4.18 | 5.26 | 10.0 % | 6.4 % |
| gain 16, 1.0 s | 4.20 | 5.21 | 10.1 % | 6.8 % |
| 이전 규칙 (gain 8, 0.7 s) | 3.80 | 5.21 | 8.7 % | 5.1 % |

- 상위 후보끼리의 검증 J 차이(0.2 이내)는 작습니다. gain 14–16, 0.7–0.9 s 범위면 비슷합니다.

## 4b. 착석 G 제어와 v9 체형 스케일 (`oasis_rt/g_residual_control.py`, `oasis_rt/body_scale.py`)

10/28 착석 시험의 제어기는 **측정 G 기본 곡선 + v8 actor의 제한된 보정**입니다(`docs/reports/20261028`). v9는 이 구조를 고정한 채 **체형 스케일 하나만** 더합니다.

```
기본각   base(|G|) = 0.01 g 0° → 0.0625 g 10° → 1 g 20° (구간 선형)      예측만: 최대 10°, 100 ms 확인
v9       base' = min(s · base, 20°),  preview' = min(s · preview, 10°)     s: 세션마다 한 번 정해 고정
보정     ±1.5° (actor 각 − 학습 prior 각), 1 g에서 0°                      (그대로)
s        = clip(1 + K_W (r_w − 1) + K_T (r_t − 1), 0.9, 1.1)               K_W = −1.2, K_T = 0 (앉은키는 기록만)
r_w      = (어깨폭 px / 화면 폭) / 0.2665          r_t = (어깨→골반 높이 px / 화면 높이) / 0.424
```

- **기준 사용자**는 10/28 최종 세션(03:31, `2odf4ms1`)의 착석자입니다. 이 사람에게는 현재 설정이 잘 맞는다고 확인했으므로 s = 1입니다.
  - 기준값은 그 세션의 Pi RTMPose 뷰어 녹화(`pose-rpi.webm`, sha256 `93f7a0b2…`)에서 쟀습니다. 0–61 s의 294프레임에서 오버레이의 어깨·골반 점을 읽었습니다(`sim/v3/reference_body_from_video.py`, `results/v9/reference_user.json`).
  - 결과는 어깨폭 0.2665(화면 폭 대비, 변동 2.8 %), 어깨→골반 높이 0.424(화면 높이 대비, 변동 3.6 %)입니다. 62 s 이후는 영상 디코딩이 깨져 제외했습니다.
- **다른 착석자**는 세션 전에 받는 카메라 중립 파일(`oasis.rtmpose.neutral.v1`, 작업자 확인)로 r을 계산합니다(`body_scale.neutral`). 주행 중 프레임으로 다시 계산하지 않습니다.
  - 화면 대비 비율이라 해상도와는 무관합니다. 하지만 카메라 위치·렌즈·모드·좌석 위치가 10/28과 같아야 합니다.
  - r이 0.7–1.4를 벗어나면 구도가 바뀐 것으로 보고 시작을 거부합니다.
- **바뀌지 않는 것:** 방향 선택, 예측 확인 시간, RL 보정 폭, 필터(τ 0.3 s), 속도 게이트, 압력 해제(2500 count), CAD·STM·IK 투영, 학습 관측의 체형값(`profile.from_camera: false`)
- `body_scale.enabled: false`(기본)이면 s = 1이고, 10/28 제어기와 같은 출력입니다. 시험으로 고정했습니다.

**튜닝** (`sim/v3/tune_body_scale.py`, `results/v9/body_scale.json`)
- 시뮬레이터 v8에서 Pi와 같은 G 제어기 코드를 그대로 import해 돌렸습니다.
  - v8 actor는 배포 profile(75 kg / 0.42 m / 0.58 m)을 봅니다.
  - 보드 설정은 시험과 같습니다(STM yaw 10 °/s, 상한 20°).
- 체형 9개(어깨폭 0.36–0.48 m, 앉은키 0.50–0.66 m) × s 9개(0.8–1.2)를 같은 48 에피소드로 비교했습니다(시드 3000+, 레벨 1·2).

## 5. RL 정책 (SAC 잔차)

### 5.0 알고리즘 선택: SAC 유지

이 문제의 특징:
- 행동이 연속 2차원입니다.
- 관측이 부분적입니다. 인체 상태를 직접 볼 수 없어 9프레임 이력을 씁니다.
- 시뮬레이터에는 특권 정보가 있습니다(CoM, 접촉력, 파라미터).
- 보상은 쌍둥이 대비라서 잡음이 큽니다.
- 시뮬레이터가 느립니다. 코어당 약 55 스텝/s, 에피소드 40 s.
- 배포 대상은 결정적 MLP 하나이고, 규칙 위의 잔차입니다.

| 후보 | 장점 | 이 문제에서의 단점 | 판단 |
|---|---|---|---|
| **SAC** | off-policy라 표본 효율이 높음. 엔트로피 탐색이 잡음 많은 DR에 강건. 평균 행동이 결정적이라 잔차·배포가 단순 | α 조정, Q 과대추정 (클립·α 상한으로 처리) | **채택** |
| TD3 | 결정적, 안정적 | 탐색 잡음을 수동으로 정해야 함. 확률적 보상에 덜 강건 | 이점 없음 |
| PPO | 안정적, 병렬화 쉬움 | on-policy라 표본이 10–50배 필요. 느린 시뮬레이터에서 200k 스텝 예산으로는 부족 | 제외 |
| TQC / DroQ (SAC 변형) | 과대추정 감소, 표본 효율 | 구현 복잡도 대비 이득이 점진적 | 다음 버전 후보 |
| 모델 기반 / MPC | 물리 모델 활용 | 인체 모델 불확실성이 크고, Pi 연산 부담 | 제외 |

유지하는 구조:
- 비대칭 critic(특권 상태 31개)
- 튜닝 규칙 위의 잔차
- CAPS 매끄러움
- 이력 K = 8
- 보상 스케일 20, α ≤ 1, 그라디언트 클립 10

```
a = clip( rule(o) + 0.25 · tanh(μθ(x)), −1, 1 )    x = 정규화된 관측 이력 9 × 57 = 513 (±5 클립)
μθ : 513 → 256 → 256 → 2, ReLU                    결정적 실행 (평균 행동)
```

- **규칙 위의 잔차**입니다. 신경망 출력이 0이면 정확히 튜닝 규칙이 됩니다. v8에서 신경망이 바꿀 수 있는 폭은 ±0.25(행동 단위, yaw 약 ±2.5°)입니다. v7은 ±0.5였습니다.

### 5.1 v8 첫 학습(`v8a`)이 규칙보다 나빴던 이유

v7과 같은 보상·설정으로 v8 환경에서 학습한 두 시드(`v8a_s0`, `v8a_s1`)는 평가 점수가 튜닝 규칙보다 낮았습니다(같은 에피소드 차 −7.1, −5.5). 보상을 항별로 나눠 보면 원인이 보입니다(`sim/v3/reward_diag.py`, `results/v8/reward_diag.json`, 평가 은행 48 에피소드 평균).

| | CoM 이득 | 출력 변화 | 추가 압박 | 과압박 | **보상 합** | **평가 점수** |
|---|---|---|---|---|---|---|
| 볼스터 열림 (passive) | 0 | −0.3 | 0 | 0 | **−0.3** | **0** |
| 튜닝 규칙 | +15.4 | −8.4 | −8.3 | −20.0 | **−21.8** | **+4.7** |
| `v8a_s0` | +14.6 | −6.7 | −8.3 | −11.2 | −12.2 | −2.4 |
| `v8a_s1` | +13.7 | −6.4 | −7.3 | −16.9 | −17.3 | −0.8 |

- **보상과 평가 기준이 서로 다른 제어기를 좋다고 합니다.**
  - v7 보상으로는 튜닝 규칙이 아무것도 안 하는 것보다 나쁩니다(−21.8 vs −0.3). 비용이 CoM 이득의 2.4배입니다.
  - 평가 점수로는 규칙이 낫습니다(+4.7). 규칙과 passive 중 어느 쪽이 나은지 두 기준이 일치한 에피소드는 35 %뿐입니다.
- **RL은 자기 보상은 잘 올렸습니다**(규칙 대비 +9.6, +4.5). 하지만 그 방향이 "덜 움직이기"라서 평가 점수가 떨어졌습니다.
- **CoM 항의 가중이 다릅니다.**
  - 보상은 절대 CoM²(2 cm 단위)라서, 크게 흔들리는 소수 에피소드가 지배합니다.
  - 평가는 에피소드마다의 상대 감소율이라서, 모든 에피소드가 같은 무게입니다.
  - 그래서 RL은 절대 CoM 이득을 거의 지키면서(15.4 → 14.6) 평균 감소율은 크게 잃었습니다(10.3 → 2.4 %).
- **데이터 한계도 겹칩니다.**
  - 볼스터가 줄이는 몸의 움직임 자체가 작습니다. 볼스터를 연 채의 CoM RMS 중앙값이 0.59 cm이고, 규칙은 이것을 약 10 % 줄입니다(약 0.6 mm).
  - 볼스터 → 몸 권한은 직접 측정한 값이 아닙니다. 실차 1회(동승자)와 벤치 2명의 압력 비로 간접 추정했습니다(`PARAMS_FINAL.md`).
  - 구동기도 느립니다(yaw 약 5–6 °/s). 좋은 미리보기를 가진 규칙이 이미 제어 가능한 범위의 대부분을 씁니다.
  - 그래서 RL이 규칙과 전혀 다른 더 좋은 제어를 찾으리라고 기대하기 어렵습니다. **v8은 규칙에서 출발해 조금씩 조정하는 방식으로 바꿨습니다.**

### 5.2 v8 학습: 튜닝 규칙에서 시작해 조정

- **보상 = 평가 점수** (`sim/v3/overlays/reward_score.yaml`, `env_v3` `reward.mode: score`). 스텝마다 아래를 더하면 에피소드 점수가 됩니다.
  ```
  r = 50 (y_twin² − y²) / Σ_에피소드 y_twin²                       → CoM RMS 감소율 [%] (1차 근사)
      − (50 · [ΔF > 20 N] + 100 · ((ΔF − 20)/20)²₊) / 스텝 수      → −0.5 × 20 N 초과 시간 [%] − 100 × 과압박²
      − 0.01 Σ Δa²  − trip                                          → 작은 매끄러움 항 (규칙의 떨림 ≈ 0.3점)
  ```
  - y는 상체 CoM 횡변위(÷ 2 cm), y_twin은 같은 사람을 볼스터를 연 채로 둔 쌍둥이입니다. 쌍둥이는 정책과 무관하므로 에피소드 시작 때 한 번 미리 돌려 분모(Σ y_twin²)를 구합니다(바닥값 1 mm RMS).
  - ΔF는 쌍둥이 대비 볼스터가 더한 압박입니다.
  - 볼스터를 연 채로 두면 보상이 정확히 0(첫 스텝 −0.01)입니다. 이 보상은 검증 에피소드에서 규칙을 passive보다 높게 봅니다(감사 10번).
- **규칙에서 출발** (`sim/rl/sac_asym.py`, 실행 `v8_s0`–`v8_s3`, prior = §4 규칙)
  - 처음 20k 스텝은 critic만 학습합니다. 이 동안 정책은 규칙 + 작은 탐색 잡음입니다(`--actor_delay 20000`).
  - 출력 층은 0으로 시작합니다(신경망 출력 0 = 규칙). 탐색 표준편차는 e⁻¹로 시작합니다(`--init_log_std −1`, v7은 1). 워밍업 잡음은 0.1입니다.
  - 보정 크기에 벌점을 둡니다: 0.02 · |tanh μ|²(`--res_l2`). 근거가 약한 곳에서는 규칙에 머무르게 합니다.
  - 비대칭 SAC입니다. 비평가는 시뮬레이터 내부 상태 31개를 더 봅니다(CoM, 접촉력, 파라미터). 배우(actor)는 관측만 봅니다.
  - 20 Hz, γ 0.98, 200k 스텝입니다. 난이도 레벨은 0→2로 올립니다(학습의 60 %까지). CAPS 매끄러움(시간 2.0, 공간 0.5)을 겁니다.
  - 4 시드를 GPU에서 동시에 학습했습니다(`--device auto`, RTX 4070 SUPER, 시드당 약 19 ms/스텝, 약 1시간). 신경망이 작아 GPU는 한 시드를 빠르게 하기보다 여러 시드를 동시에 돌리는 데 이득입니다(CPU 2 시드 16 ms/스텝).
- **환경 무작위화 (v8 = v7 + 보드 구동기 + Collector 입력, 범위와 근거는 `sim/v3/final/PARAMS_FINAL.md`)**
  - 차량: BeamNG급 동적 단일궤적 모델(`scenario.dynamic_bicycle`).
    - 타이어 포화, 조향 랙 지연·속도·락
    - 롤(체감 a_y = 차 a_y + g sin 롤 + 경사)
    - 휠베이스 2.4–3.0 m, 조향비 15 ± 1.2, 코너링 강성, 노면 μ
  - 탑승자: 질량, 체형, 반사 지연, 강성, 문 지지 유무. 운전자 / 동승자. 실차 H2 일치 회전 16/16로 보정.
  - 좌석: 권한 22.2 counts/° [14, 35](H3 일치 데이터 + 기하), 접촉 강성, 틈(체형 B), 상·하 패드 분담.
  - 센서
    - 압력 잡음 20–60 counts(벤치)
    - pose 9.5–11 Hz, 잡음 0.4–1.0°
    - BeamNG Collector 행 25–60 Hz. 도로 정보 없음, 요레이트 = a_y / max(v, 5)(Pi와 같은 식)
  - 구동기: OASIS_FALLBACK v2 20 ms 프레임, 서보당 2 µs, STM 튜닝 속도 {10, 20} °/s(0.2 / 0.8), yaw 상한 {15, 20}°(0.3 / 0.7), CAD pitch 상한. 0 → 9° 1.52 s(감사 6b)
  - 오버레이: `sim/v3/final/overlays.txt`(v7 목록 + `fb_a2` + `beamng_drive_collector` + `reward_score`).
- **체크포인트 선택**
  - 25 에피소드마다 스냅샷을 남깁니다.
  - 마지막 6개와 prior 규칙을, 규칙 튜닝과 같은 검증 에피소드 48개(시드 3000+, 레벨 1·2)에서 같은 점수(J)로 비교합니다(`select_ckpt.py --criterion score --n 48 --levels 1 2 --prior 16 6`).
  - 배포할 실행도 이 검증 J로 고릅니다(4 시드 중 최고). 평가 은행(시드 1000+)은 결과 보고에만 씁니다. v7은 평가 은행 J로 골랐습니다.

  - 규칙보다 크게 나아지지 않는 것은 §5.1의 데이터 한계와 맞습니다. 볼스터가 줄일 흔들림이 작고, 권한 추정이 간접적이며, 구동기가 느립니다.
- **시드 차이가 큽니다.**
  - 네 시드 모두 검증 J로는 규칙보다 높았습니다. 그러나 평가 은행에서는 두 시드(`s0`, `s2`)가 꼬리 에피소드에서 크게 잃었습니다(p10 −9.3, −15.4; 규칙 −0.56).
  - 10 % 절사평균 J는 꼬리를 잘라 내므로, 검증 J만으로는 이 위험이 보이지 않습니다.
  - `v8_s1`은 두 평가에서 모두 규칙 이상인 유일한 시드입니다. 다음 버전에서는 선택 기준에 꼬리(p10)나 같은 에피소드 차의 평균을 넣어야 합니다.
- **압박:** RL의 20 N 초과 시간은 규칙과 비슷하거나 약간 적습니다(L2 6.9 vs 7.5 %). 최대 추가 압박은 L2에서 46 vs 42 N으로 큽니다.
- **FB V6(cold fallback)보다는 분명히 낫습니다.**
  - J는 규칙 3.93, FB V6 1.70입니다. FB V6이 규칙보다 나은 에피소드는 48개 중 10개입니다(Wilcoxon p < 0.001).
  - FB V6은 덜 누르지만(2–3 %), CoM도 덜 줄입니다(3.5–4.4 %).
- **배포:** `v8_s1`을 `control.mode: rl`로 두고, 튜닝 규칙을 hot fallback으로 둡니다.
  - 시뮬레이터에서는 `control.mode: rule`도 같은 성능입니다.
  - L2 벤치 주관평가에서 RL이 규칙보다 체감이 나쁘면 `rule`로 바꾸기를 권합니다.
- **관측 제거 실험** (`results/v8/obs_ablation.json`, `v8_s1`, 24 에피소드, 점수 변화):
  - a_y 미리보기: **−8.6 [−21.8, +0.7]**
  - 체형 + 휴지 압력: −1.1 (유의하지 않음)
  - 현재 차량 상태, 압력, pose, 보고 각도: ±0.5 안
  - 성능은 미리보기에서 나옵니다(v7과 같음). 압력과 체형 단서는 거의 쓰지 않습니다.
- **체형별** (`results/v8/body_type_eval.json`, 각 24 에피소드, RL − 규칙):
  - A형 −0.63 [−3.01, +1.45], B형(마른 체형) −0.59 [−1.75, +0.15], 넓은 체형 −4.74 [−13.0, +0.33]
  - RL이 규칙보다 나은 체형은 없습니다. 넓은 체형에서는 CoM 감소가 작습니다(7.6 vs 12.1 %).
- **짧은 시나리오** (`models/v8/trace_*.json`, git 밖, `run_final.sh` trace 단계, 14 s, CoM RMS 감소 규칙 / RL, 최대 추가 압박):
  - 1000 도심 회전: 4.7 / 4.6 %, 7.9 / 7.9 N
  - 1001 차선 변경: 3.3 / 3.3 %, 2.8 / 3.0 N
  - 1003 실차 재생(운전자): 29.7 / 29.7 %, 28.0 / 24.4 N
  - 1004 도심 회전: 18.2 / 14.7 %, 36.1 / 28.4 N
  - RL은 대부분 규칙과 같은 각도를 내고, 가끔 덜 조여 압박을 줄입니다.

## 8. 세션과 fallback (`oasis_rt/app.py`)

```
정책 준비 (모델·백엔드 검사)  ──실패──► control.cold_fallback: fb_v6 (null이면 시작 거부)
보드 handshake: HELLO v2(270°, 2 µs, lease 500) → FB_OFF → CAD(sha256) → TUNE(고정) → DISABLE → FSR HELLO → START_12,15 → STATE(OFF)
유효 BeamNG 행 + PWM OFF 2 s 연속 ──► FB_ARM,<floor+1>,<tune rev> (한 번)
fresh armed STATE 중립(pose = target = 0) 0.5 s 안
rl / rule: 중립에서 압력 기준선 2 s (lease는 BeamNG가 유효할 때만)
제어: rl / rule 20 Hz, fb_v6 50 Hz;  PING 100 ms · STATE 100 ms · SET ≥ 40 ms · 압력 PING 1 s
어떤 입력·보드·정책 오류든 → FB_OFF → DISABLE → STATE로 OFF 확인 → 종료 (자동 재ARM 없음)
```

| 상황 | 동작 |
|---|---|
| 액터 예외 / NaN / inf | 튜닝 규칙으로 전환, **세션 끝까지 유지(latched)** |
| 시작할 때 통과하는 액터 백엔드가 없음 | 처음부터 규칙 |
| 예측기 출력 NaN | 그 tick은 현재 a_y 유지(hold) |
| 모델이 다른 구동기용 (manifest `actuator.mode` ≠ `fb_a2`, 예: v7) | 규칙으로 세션 (`control.actuator_mismatch: rule`; `run`이면 경고만) |
| STM `yaw_rate` < 학습 최소(10 °/s) 또는 `yaw_max` < 학습 최소(15°) | 규칙으로 세션 |
| 모델 패키지 없음 / 해시 불일치 | FB V6 (cold fallback) |
| ARM 전 입력 문제 | 2 s 검증을 처음부터 (ARM 안 함) |
| ARM 후 입력 문제 | OFF, 종료 |

- 규칙 파라미터는 모델 manifest의 prior(`ff_gain`, `ff_idx`)입니다. RL이 학습할 때 기준으로 삼은 규칙과 같고, `results/v8/rule.json`의 best와도 같습니다.
- FB V6는 FB의 `Settings` 기본값 위에서 돕니다. 여섯 개 튜닝값(yaw/pitch 상한·속도, 최대 반응 a_y, pitch 배율)은 STM이 확정한 값으로 바뀝니다(`tuning.apply_firmware_tuning`). 조향 선제 부호는 `beamng.steer_sign`을 따릅니다.
- 시험 (`deploy/runtime/tests`)
  - `test_app_fb.py` 16개 (OASIS_FALLBACK v2 모의 보드 + 합성 Collector 행)
    - RL / 규칙 / FB V6 세션
    - 끊김·잘못된 행·조향 부호·충격(0.15 s, rl / rule) → OFF
    - lease 만료, 엔벨로프, hot / cold fallback, 구동기 검사, 확인 항목 없으면 거부
  - `test_runtime.py` 16개 (제어기·인터락·백엔드, 이전 FW v6 링크)

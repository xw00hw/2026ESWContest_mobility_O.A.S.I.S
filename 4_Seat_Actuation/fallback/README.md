# BeamNG 횡가속도용 기본 볼스터 제어

BeamNG 차량 신호와 ESW 압력시트를 연결하는 **규칙 기반 위치 제어 + 압력 증가 감시**입니다. RL·카메라·영상·자세 추정값은 사용하지 않습니다. 좌우 구조물의 yaw만 사용하고 pitch는 0°로 유지합니다.

**2026-10-26 현재 설정: 왼쪽·오른쪽 Yaw 각각 0~20°, 양쪽 Pitch 0°입니다.** 사용자가 요청한 20°를 위치 명령 상한으로 적용합니다. 속도 제한은 2°/s, 최대 요구량 기준은 횡가속도 크기 0.30g로 유지합니다. `pressure_fraction=0.20`은 실시간 압력 증분 감시에만 쓰며 각도 상한을 역산하지 않습니다.

이 작업은 별도 `feat/beamng-pressure-fallback` 브랜치에서 작성했습니다. 실제 보드 업로드, COM 연결, 모터 구동은 하지 않았습니다. 현재 사용 중인 압력 전용 프로그램과 설치된 BeamNG 수집기는 변경하지 않았습니다.

## 제어의 의미

차량 좌표는 +x 전방, +y 왼쪽입니다. **ay>0이면 상대적인 몸 쏠림은 오른쪽**이므로 오른쪽 볼스터를 몸 쪽으로 닫고, ay<0이면 왼쪽을 닫습니다. 사용자가 양쪽 모두 +yaw가 몸 쪽으로 닫히는 방향이라고 확인했습니다.

고정된 시트는 BeamNG 차량의 횡가속도를 없애거나 동일한 관성력을 만들어 내지 못합니다. 이 코드는 가상 주행 신호에 반응하는 위치 동작이며, 실제 자세 쏠림 감소나 힘 상쇄 효과는 아직 측정하지 않았습니다.

1. 원래 수신시각·시뮬레이션 시각·품질 플래그를 검사합니다.
2. 횡가속도를 0.20초 저역통과 필터로 처리합니다. 0.03g에서 활성화, 0.02g 이하에서 해제합니다.
3. 0.30g를 위치 동작의 최대 기준으로 삼습니다. 정규화된 요구량은 0~1이며 **요구량 × 20°**를 선택된 측면의 목표로 합니다. 반대쪽은 0°입니다. 필터·압력 감시·속도 제한을 통과해야 해당 목표로 진행합니다.
4. 구조물 목표 각도 변화율은 최대 2°/s이므로 0→20° 목표 변화에는 최소 10초가 필요합니다. 입력 필터와 펌웨어 추종 때문에 더 오래 걸릴 수 있으며 실제 축 도달 시간을 보장하는 값은 아닙니다. 펌웨어 PWM 변화는 20ms당 축별 최대 2µs입니다. 방향 전환은 중립 목표에 도달한 상태를 거칩니다.
5. 새로 측정한 중립 압력 대비 채널별 증가를 감시합니다. 초과 시 중립으로 되돌리는 목표를 내리고, 크거나 지속되는 초과는 PWM OFF로 고정합니다. 압력이 작다고 각도를 계속 올리는 적분 제어는 없습니다.

## 실제 데이터에서 채택한 것

Drive `볼스터제어데이터/bench_20261025_pose_v1.zip`의 압력 ADC, 모터 명령·상태, 측정 계획·시간·설정만 선택적으로 읽었습니다. 영상·이미지·프레임·랜드마크·포즈 추정·영상과 결합된 분석 표는 사용하지 않았습니다. 원시 파일은 Git 밖에 보존합니다.

[분석 프로파일](profiles/bench_20261025.json)은 55개 축 단독 명령점, 132,660개 실제 ADC 표본으로 만들었습니다. 자세한 근거와 재현 방법은 [분석 노트](profiles/bench_20261025_NOTES.md)에 있습니다.

2026-10-25 사용자 확인:

| 센서 | 착석자 기준 위치 |
|---|---|
| A1_C0 | DR: 오른쪽 아래 |
| A1_C1 | UR: 오른쪽 위 |
| A1_C2 | DL: 왼쪽 아래 |
| A1_C3 | UL: 왼쪽 위 |

모터 혼 영점·방향·링크·센서 위치는 측정 당시와 같고, 측정 중 특별한 불편이나 기구 걸림은 없었다고 확인했습니다. 원본 프로파일의 `physical_channel_mapping=null`은 원자료의 상태를 보존하며, 새 확인사항은 `config.example.json`과 분석 노트에 따로 기록합니다.

같은 각도라도 세션에 따라 압력 변화의 부호가 달랐습니다. 따라서 **압력→각도 역함수, 일정한 압력 증가율, N/Pa 환산**을 만들지 않았습니다. ADC는 명목 3.3V 기준 전압으로만 사용합니다. 채널 평균과 p95는 실제 힘이나 접촉 면적을 뜻하지 않습니다.

기록상 yaw 범위는 0~27°, pitch는 ±8°입니다. 이것은 **구조물 각도**이며 모터 출력축 각도와 다릅니다. 펌웨어의 독립 하드 제한도 yaw 0~27°·pitch ±8°를 유지하지만, 현재 호스트 운용은 **yaw 0~20°·pitch 0°**로 더 좁게 제한합니다. 펌웨어는 C4_R8 역기구학으로 네 DS5180SSG 270° 서보의 펄스를 계산합니다. 기록된 yaw 0→27° 경로의 펄스 변화 최대 504µs는 이 환산에서 약 68.04°의 크랭크 회전에 해당합니다. 실제 축 위치 피드백은 없습니다.

### 현재 위치 상한과 압력 감시

`max_yaw_deg=20.0`을 양쪽 위치 상한으로 사용합니다. `pressure_fraction=0.20`을 바꾸어도 이 각도 상한은 바뀌지 않습니다. 압력 측정값으로 각도나 힘을 역산하지 않으며, 20°는 사용자가 선택한 시험 상한이지 데이터가 보장한 압박 한계가 아닙니다.

실시간 압력 감시에는 각 채널의 과거 중립 p95 대비 관측된 양의 증가 범위에서 20%를 증분 기준으로 사용합니다. 새 착좌 중립 평균을 기준선으로 삼고, 과거 중립 구간 표준편차 3배(최소 0.01V)를 잡음 허용치로 더합니다. 증분 기준+잡음 허용치 초과가 0.1초 지속되거나, 증분 기준+잡음 허용치 2배를 즉시 넘으면 OFF입니다. 착좌 기준선의 변동·과거 기준선과의 차이도 확인합니다. 이 감시 때문에 입력 요구량이 커도 실제 명령이 20°에 도달하기 전에 중립 복귀 또는 OFF가 발생할 수 있습니다.

20%는 **과거 전압 증가 범위에서 정한 소프트웨어 감시 설정**입니다. 횡가속도 힘의 20%, 실제 압력의 20%, 사람에게 검증된 안전 한계라는 뜻이 아닙니다.

### 과거 상한 계산 — 현재 운용에는 적용하지 않음

2026-10-25 초기 구현은 과거 p95 증가 경로의 누적 최대값에서 20% 지점을 역산하고 5°를 추가 상한으로 적용했습니다. 그 결과는 왼쪽 약 **0.497°**, 오른쪽 약 **0.300°**였습니다. **2026-10-26 사용자 요청으로 이 정적 각도 상한 계산을 폐기하고 양쪽 20°로 변경했습니다.** 원본 프로파일·분석 노트·당시 검증 기록의 작은 각도는 역사 자료로 보존하며 현재 명령 범위를 나타내지 않습니다. 과거의 1° 간격 보간·분해능·압력 응답 한계도 그대로 기록으로 남깁니다.

## 구성

| 파일 | 역할 |
|---|---|
| `beamng.py` | CSV/UDP 메시지, 원래 시각·단위·순서·품질 검사 |
| `beamng_bridge.py` | 기존 v0.3 수집기의 저장 경로 뒤에서 제어용 사본 전달 |
| `profile.py` | 사용자 지정 20° 위치 상한, 설정 검증, 기록 기반 압력 증분 기준·응답 한계 표시 |
| `controller.py` | 중립 기준선, 횡가속도 위치 명령, 압력·정지 상태기계 |
| `serial_link.py` | 압력 12채널 수신, fallback 전용 펌웨어 확인·명령·ACK |
| `runner.py` | 명시적 실제 연결, 한 실행 루프에서만 제어·유효시간 갱신 |
| `replay.py` | 실제 장치 없는 차량 CSV 재생·분석 기록 |
| `tests/` | 가짜 소켓/UART/시계 및 실제 기록 파일을 이용한 오프라인 검증 |
| `../stm32/FALLBACK_PROTOCOL.md` | 선택형 C 펌웨어, 배선·PWM·프로토콜·중단 동작 |

Python 3.10 이상입니다. 실제 연결에는 pyserial, 그림 출력에는 matplotlib, 프로파일 재생성에는 NumPy/PyArrow가 필요합니다. 기본 `inspect`와 그림 없는 차량 `replay`는 표준 라이브러리만 사용합니다. 영상 관련 라이브러리는 불러오지 않습니다.

## 지금 실행할 수 있는 오프라인 확인

작업 폴더는 저장소의 `4_Seat_Actuation`입니다. 아래 명령은 포트·장치를 열지 않습니다.

```powershell
python -m fallback --config fallback/config.example.json inspect
python -m unittest discover -s fallback/tests -v
python -m fallback --config fallback/config.example.json replay --vehicle-csv C:\path\to\vehicle.csv --out C:\path\to\new_replay --plot
python -m fallback.beamng_bridge --collector-root C:\path\to\BeamNG_Collector_v0_3 --check-only
```

재생의 출력 `report.json`에는 입력·프로파일·코드 해시, 설정 전체와 품질 통계가 남습니다. `vehicle_demand_replay.csv`와 선택적 PNG는 **차량 요구량과 후보 각도** 분석입니다. 실시간 압력 피드백, 모터 추종 궤적, 실제 제어 효과를 재현한 결과가 아닙니다. 재생에서는 품질이 회복된 구간을 다시 분석하지만, 실제 실행은 오류 후 자동 재시작하지 않습니다.

## 이후 하드웨어 시험을 시작할 때

이 절의 명령은 이번 구현 과정에서 실행하지 않았습니다.

1. 기존 압력 GUI가 포트를 사용 중이면 정상 종료합니다. 제어 코드는 다른 프로그램을 강제 종료하거나 포트를 자동 선택하지 않습니다.
2. 모터 전원 OFF·USB 유지 상태에서 `OASIS_FALLBACK_CONTROL=ON`으로 빌드한 전용 ELF를 별도 업로드합니다. 기본 통합 v6나 압력 전용 펌웨어에는 이 호스트가 ARM하지 않습니다. 빌드 방법과 검증 기록은 `../stm32/FALLBACK_PROTOCOL.md`, `../stm32/build_fallback/build_receipt.json`을 참고합니다.
3. `config.example.json`을 실행용 설정으로 복사하고 현재 착좌자와 중립 적용 가능 여부를 설정합니다. 양쪽 Yaw 상한은 요청된 20°이며 Pitch는 0°입니다. 이미 확인된 배선·센서 위치·닫힘 방향과 사용자가 선택한 시험 범위(`initial_range_checked`)는 true입니다. 이는 새로운 물리 검증을 수행했다는 뜻은 아닙니다. 실제 시험 전까지 `neutral_start_clear`와 `same_recorded_participant`는 false로 남아 있으며, 현재 착좌 기준선은 매번 새로 측정합니다.
4. 기존 수집기 GUI와 중복 실행하지 않고 아래 bridge launcher로 수집기를 실행합니다. 원본 파일·바탕화면 바로가기·설정은 수정하지 않습니다.
5. BeamNG 수신을 확인한 다음 명시적으로 `run --arm`을 실행합니다. 2초 동안 차량·압력 데이터가 정상이어야 ARM하며, ARM 후 중립에서 다시 2초의 압력 기준선을 수집합니다.

```powershell
python -m fallback.beamng_bridge --collector-root C:\path\to\BeamNG_Collector_v0_3
python -m fallback --config C:\path\to\reviewed_config.json run --port COM11 --arm --out C:\path\to\new_run
```

설정만 읽는 기본 명령은 구동하지 않습니다. 실제 실행에는 `--config`, `--arm`, 구체적인 포트가 모두 필요합니다. 최초 ARM은 2026-10-28 확정된 D3/D4/D5/D6 = 1800/1800/1200/1200µs 영점을 적용하므로 현재 축 위치와 다르면 움직일 수 있습니다. 서보의 전원을 켰다는 사실만으로 현재 위치를 알 수는 없습니다.

## 신호·시간·오류 계약

| 경로 | 계약 |
|---|---|
| BeamNG → 기존 수집기 | UDP 127.0.0.1:64256, 기존 수집기 하나만 수신·원본 저장 |
| 수집기 → fallback | UDP 127.0.0.1:64257, nonblocking 사본; 원래 `host_monotonic_ns` 유지 |
| 차량 신호 | `linear_acc_y_mps2` 중력 제외, +y 왼쪽; 속도 m/s; 종가속도 m/s² |
| 기타 기록 | 조향각 deg, throttle/brake 입력 정규화 값; 추종 목표에는 사용하지 않음 |
| 시간 | 같은 PC의 perf_counter_ns; 벽시계로 보간·재타임스탬프하지 않음 |
| 차량 품질 | config/미분 유효, 순번·stream·session·시간 연속; abs(ay)≤12, abs(ax)≤15m/s² |
| 정지 | 속도 1m/s 미만이면 정상 신호 확인 후 중립 목표 |
| 호스트 신선도 | 차량·보드 상태 최대 200ms, 압력 UART 계층 최대 100ms |
| 압력 | 12bit ADC ×3.3/4095, C0~C3 완전 연속 스캔만 게시; 오래된 채널 재사용 금지 |
| UART | 460800bps, 요청 하나만 대기, 응답 200ms 제한, 명령별 정확한 ACK |
| 제어 | 좌우 Yaw 0~20°·Pitch 0°, 최대 2°/s; 명목 50Hz, 변경 목표 최대 25Hz |
| ARM/lease | 명시적 새 세션, 독립 FB_PING; 압력 PING은 모터 유효시간을 갱신하지 못함 |
| 펌웨어 | 20ms 추종, 최대 2µs/축, 네 출력 preload 동시 반영, lease 검사 기준 500ms |
| 오류 | 입력 지연·이상·재시작·ACK 실패·압박 초과 시 OFF 고정, 자동 재ARM 없음 |

단일 제어 루프가 건강한 판단을 내린 경우에만 모터 heartbeat를 보냅니다. 입력 손실 뒤 별도 백그라운드 스레드가 모터를 유지하지 않습니다. 펌웨어 lease는 검사 기준 500ms이며 HAL 호출과 실행 지연이 더해질 수 있습니다. 독립 watchdog은 명목 2초이며 실제 LSI 오차·부하·파형 지연은 실측하지 않았습니다.

`Ctrl+C`와 오류는 `FB_OFF`를 요청하고 새로운 OFF 상태가 수신됐는지 기록합니다. **PWM OFF는 모터 전원 차단이나 압박 해제 보장이 아닙니다.** 자동으로 중립으로 크게 이동시키지 않으며 실제 기구의 하중 상태는 알 수 없습니다.

실행 기록은 `manifest.json`, `control.jsonl`입니다. 수집기 원본 차량 CSV/JSONL 저장은 그대로 이어집니다. control 로그에는 실제로 받은 차량 key·collector session/config hash, 최신 완전 압력 스캔, 명령 상태, 기준선과 정책 결정이 남습니다. 압력은 제어 주기에서 선택한 최신 스캔이므로 전체 100Hz 원자료 아카이브라는 의미는 아닙니다. MCU `STATE`의 각도·moving은 명령 상태이며 실제 축 센서 측정이 아닙니다.

## 검증 범위와 다음 확인

현재 검증은 Python 단위/통합 시험, 가짜 UART·소켓·시계, 실제 기록 CSV 재생, 생성 ELF의 레지스터/프로토콜/추종 에뮬레이션까지입니다. 소스와 기록에 대한 독립 리뷰도 수행했습니다. 실제 PWM 파형·구동 지연·압박감·신체 지지 효과는 확인하지 않았습니다.

다음 단계는 사용자가 착좌한 상태에서 BeamNG 신호를 받아, 양쪽 20° 상한·Pitch 0°·2°/s 제한과 압력 감시를 함께 확인하는 실제 시험입니다. 압력·명령 상태를 기록하고 중립 복귀, 방향 전환, 입력 중단 동작과 실제 압박감을 확인합니다. 영상 없이 수행할 수 있으며, 이번 코드·문서 변경 자체로 실제 업로드나 구동을 시작하지 않습니다. 이후 동일 주행 시나리오의 OFF/규칙 제어를 비교합니다. 현 자료로는 압력의 물리 단위나 횡가속도 상쇄율을 산출할 수 없습니다.

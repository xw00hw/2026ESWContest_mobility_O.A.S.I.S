## V7: 큰 횡가속도는 각도 포화, 충격 의심 시 모터만 OFF

기존의 단일 샘플 `|ay|>12m/s²` 또는 `|ax|>15m/s²` 자동 종료를 실험 A에서 제거한다. 유효한 큰 횡가속도는 기존 필터·좌우 전환 조건을 거쳐 설정된 최대 목표에 포화된다. 기본 Yaw 15°·Pitch ±6°, CAD 결합 한계와 각도/PWM 변화율 제한은 그대로이며 최대 목표를 즉시 실제 축 위치로 적용한다는 뜻은 아니다.

`impact.py`는 횡·종가속도의 수평 합성 크기 `sqrt(ax²+ay²)`와 변화율·지속시간·짧은 구간 적분을 함께 보는 **충격 의심 휴리스틱**이다. 기본 조건은 합성가속도 25m/s² 이상, 구간 내 급변 150m/s³ 이상, 연속 고가속도 0.06초 이상, 해당 고가속도 구간의 벡터 적분 크기 1.5m/s 이상을 **모두** 만족하는 것이다. 별도로 합성가속도 60m/s² 이상은 지속시간을 기다리지 않고 OFF를 요청한다. 이 수치는 잠정 시험 설정이며 충돌의 확정 센서나 검증된 분류기가 아니다. 구간 적분은 회전하는 차량 좌표의 가속도에서 산출한 지표로 독립적인 속도 변화 측정값이 아니다.

사용자 선택에 따라 충격 의심 시 `IMPACT_OFF_PENDING`으로 모터 OFF를 요청하고 새로운 OFF 응답·상태 확인 후 `RECORD_ONLY`로 전환한다. **차량과 압력 기록은 같은 세션에서 계속하며 모터는 자동 재ARM하지 않는다.** OFF 확인이 300ms 안에 안 되거나 통신·장치·기록 오류가 생기면 전체 실행을 종료한다. 수동 `중지` 후 저장/버리기를 선택해야 다음 제어 세션을 시작할 수 있다. 원인 입력과 충격 판단 지표도 기록한다.

모터 OFF가 잠긴 이후 차량 입력의 공백·무효 샘플은 진단으로 남기며 기록 전용 상태를 자동으로 해제하거나 모터를 재구동하지 않는다. 구동 중의 200ms 입력 신선도 조건은 그대로다.

실험 A 입력의 수치 무결성 상한은 각 ax/ay 절댓값 200m/s²다. 이는 모터 각도 상한이나 충돌 기준이 아니다. 비유한 값·잘못된 파생값·시각/순서·200ms 신선도·장치 이상 검사는 계속 적용한다. 기존 압력 폴백 모듈의 기본 검증 기준은 변경하지 않는다.

사용자가 비충돌로 확인한 `V6/A_20261027_165300_984bb9af`의 12.871m/s² 피크는 종가속도 +7.251m/s², 합성 14.773m/s²인 한 샘플이었다. 13.5ms 뒤 합성값은 6.939m/s²로 낮아졌고 속력은 증가했다. 이전 14:41의 32.931m/s² 합성 피크도 단발이며 충돌 여부는 확인되지 않았다. 두 기록으로 충돌 검출율을 주장하지 않으며 양성 충돌 검증은 남아 있다. 세부 단위·시각·조건은 [RUNTIME.md](RUNTIME.md)를 따른다.

## 중지와 저장을 분리 — V6 이후 유지

- `중지`는 모터 OFF·압력 스캔 종료·기록 스레드 종료만 수행한다. V7 충격 의심은 모터만 OFF하고 기록을 계속한다. 그 외 종료 오류도 영구 기록 폴더로 자동 저장하지 않는다.
- 수집 중 데이터는 `%LOCALAPPDATA%/OASIS/ExperimentA/pending_sessions/V번호/A_날짜_고유ID/`에 임시로 쓴다. 이는 RAM 전용이 아니며, 아직 보존을 선택하지 않은 복구 가능한 디스크 기록이다.
- 모든 기록 스레드가 끝난 뒤 `저장`을 누르면 해당 기록만 `바탕화면/BeamNG Bolster A Data/V번호/A_날짜_고유ID/`로 옮긴다. `버리기`는 선택한 임시 기록만 삭제하며 기존 측정은 건드리지 않는다.
- 창을 닫아도 자동 저장·삭제하지 않는다. 다음 실행은 남아 있는 임시 기록을 찾아 저장/버리기 선택을 먼저 받으며, 선택 전 자동 제어 시작·재연결을 막는다.
- 저장 시 원본 CSV/JSONL과 기존 manifest의 바이트를 고치지 않는다. `recording.json`이 보존 상태를, `recording_relocation.json`이 원래 임시 경로와 저장 경로의 관계를 기록한다. 분석 코드는 `resolve_recording_path()`로 이전 절대 경로를 현재 기록 폴더 안에서 해석할 수 있다.

충격 의심과 데이터 무효를 구분해 원인을 표시한다. 모터 OFF 이후에도 자동 재ARM은 하지 않으며 기록을 자동으로 영구 보존하지 않는다. 200ms 제어 입력 신선도·모터 lease·기구 제한을 완화하지 않는다.

## 조향에 따른 제한된 선제 반응 — V6 이후 유지

사용자가 승인한 선제 반응의 목표 상한은 **Yaw 2°·Pitch 0°**다. 기본 가속도 반응의 초기 상한 Yaw 15°·Pitch ±6°와 각 축 2°/초는 그대로다. 선제 목표와 기존 가속도 목표를 더하지 않으며, 실제 횡가속도 반응이 시작되면 이를 우선한다. 선제 반응에도 같은 CAD·PWM·변화율·방향 전환 중립 조건을 적용한다.

시험의 선언 차량은 순정 Cherrier Vivace 160 DCT, 1.6L 터보 가솔린·전륜구동·7단 DCT다. 국산 K3 GT와 비교할 구성으로 선정한 것이며 동일한 차량 동역학을 뜻하지 않는다. 설정 파일은 `vehicles/vivace/vivace_160_DCT.pc`, SHA256은 `4eb3d9c52cb02b1a8885779090215f6b631671a3fee03296a0d32303d367ce85`다. 이는 운영자가 선택한 프로필의 계보이며 수신 차량이 그 구성을 사용하는지 자동 증명하는 식별값이 아니다. V5의 다른 차량에서 측정한 조향 이득을 옮겨 쓰지 않는다.

선제 동작 조건은 속도 5m/s 이상, 유효한 양의 정수 전진 기어, 0~1 브레이크값, 절댓값 20° 미만의 차량 Roll/Pitch, 유효한 조향값(절댓값 560° 이하)이다. 조향 5° 이하는 중립 구간이고, 같은 방향으로 0.1초 유지해야 한다. 조건이 빠지면 선제 동작만 비활성화되며 기본 입력 유효성 검사는 계속 적용한다. 가속 페달값은 기록하지만 선제 제어에 사용하지 않는다.

목표 Yaw는 다음 세 비율의 곱에 최대 2°를 곱한다. 조향각은 핸들 입력 기준이며 실제 차륜 조향각으로 환산하지 않는다.

- 조향 비율: `(abs(steering_deg)−5)/40`을 0~1로 제한한다. 45°에서 최대다.
- 속도 비율: `(v_preview²−5²)/(15²−5²)`를 0~1로 제한한다. `v_preview=max(0,v+ax×0.25초)`를 현재 속도의 0.8~1.1배 안으로 제한한다.
- 브레이크 비율: `1−0.5×brake`. 브레이크는 작은 선제 반응만 줄이며 기본 횡가속도 반응을 줄이지 않는다.

한 선제 episode는 호스트 수신 시각 기준 최대 1.5초이며 조향을 5° 이내로 되돌리거나 차량이 정지해야 새로 허용된다. 조건이 일시적으로 사라지거나 조향 방향만 바뀌어도 제한 시간을 갱신하지 않는다. 만료하면 기존 변화율 제한을 따라 복귀하므로 실제 출력이 즉시 영점이 되는 것은 아니다. 실제 또는 필터 횡가속도가 진입 기준 0.03g에 도달하거나 기본 반응이 활성화되면 기본 반응이 우선한다. 예고 방향의 반대 횡가속도가 해제 기준 0.02g 이상이어도 예고를 막는다.

이는 차량 횡가속도·실제 몸통각을 정밀 예측하는 모델이 아니라 크기와 시간이 제한된 조향 신호다. 초기 방향 설정은 `steering_to_ay_sign=1`이며 실제 차량 조향 부호와 압박 반응은 하드웨어 시험에서 확인한다. `diag.target_source`와 `diag.steering_preview`에 동작/비활성 원인·방향·Yaw·각 비율·대기/episode 시간을 남긴다. 설정과 추가 진단 설명은 [RUNTIME.md](RUNTIME.md)를 참조한다.

## 현재 시험: 양쪽 4모터 장착

사용자가 UR·UL·DR·DL 네 모터를 모두 장착했고 기존 배선·혼 영점·회전 방향·링크 길이가 같다고 확인했다. 현재 설치 설정은 `available_bolsters=both`이며 앱 장착 확인값도 모두 완료됐다. 좌회전(+ay)은 오른쪽, 우회전(-ay)은 왼쪽 볼스터를 닫고, 횡가속도가 작아지면 중립으로 돌아간다. 방향 전환은 기존 쪽의 중립을 경유한다.

고정 시트에 BeamNG의 횡가속도가 실제 가해지지는 않으므로, 양쪽 볼스터의 과도하지 않은 압박과 해제 반응을 평가한다. 압력은 비교용 기록이며 제어 입력은 BeamNG만 사용한다. 체형 보정은 하지 않는다. 아래 오른쪽 전용 구성은 V4 당시 이력이며 현재 장착 구성은 아니다.

### 이전 V4 시험: 오른쪽 모터만 장착

사용자가 UL/DL 미장착, UR/DR만 장착했다고 확인했다. 설치 설정의 `available_bolsters=right_only`는 왼쪽 Yaw/Pitch 목표를0°로 유지하고, 실제 없는 왼쪽 모터의 가상 복귀를 기다리지 않는다. UL/DL 신호핀은 펌웨어의 중립 PWM이며 OFF를 뜻하지 않는다. 두 볼스터를 모두 장착하면 이 설정을 `both`로 되돌리고 장착을 확인한다. 일반 소스 기본값은 `both`다.

실차 우회전에서는 몸이 왼쪽으로 쏠린다. 현재 고정 시트에는 BeamNG 횡가속도가 실제 가해지지 않으므로, 이번 시험은 가속도 상쇄 효과가 아니라 **과도하게 누르지 않는 오른쪽 압박과 해제 반응**을 평가한다. 제어 방향을 반전시키지 않는다.

- 좌회전(+ay): 오른쪽 볼스터의 Yaw/Pitch 움직임, 압박감, 사이드 압력 증가를 관찰한다.
- 우회전(-ay)·직진: 오른쪽의 중립 복귀와 압력 해제를 관찰한다. 왼쪽 지지 성능은 모터가 없어 평가하지 않는다.
- 양회전의 차량·압력 데이터는 모두 기록한다. `available_bolsters`, `requested_support_side`, `support_side_available` 진단과 실험 라벨을 남겨 미장착 방향을 제어 실패나 지지 효과로 해석하지 않게 한다.

압력 센서는 비교용이며 제어 입력에 사용하지 않는다. 편안한 압력값은 아직 검증되지 않았으므로 착좌 피드백과 압력 변화에 따라 Live Expressions의 각도 상한·Pitch 배율·속도를 조정한다.

## 변경된 제어 기준

- 0.15초 저역통과 필터를 거친 횡가속도를 0.03g 진입 / 0.02g 해제 히스테리시스로 처리한다.
- 횡가속도 약 0.30g에서 설정 Yaw 상한에 도달하도록 명령을 만든다.
- Pitch는 `atan2(횡가속도, 9.80665)`의 차량 가속도 벡터 각도를 패드 면에 대응시키고 CAD 결합 제한을 적용한다. 이는 실제 사람의 몸통 각도 예측이나 측정값이 아니다.
- 양의 횡가속도(차량 좌측 가속)는 착석자 우측 볼스터를 닫는다. 반대편 전환은 기존 쪽 명령 중립 복귀를 확인한 뒤 진행한다.
- 기본은 Yaw 15°, Pitch ±6°, Yaw/Pitch 각각 2°/초, PWM 각 채널 100µs/초 이하다. 최초 시험용 설정이며 실물 응답이나 상쇄 효과를 검증한 값이 아니다.
- 정지 시트는 실제 차량 횡가속도를 만들어내지 않는다. 출력은 축소된 위치 지지 신호이며 힘이나 횡가속도 상쇄율을 지시하는 제어가 아니다.

표 영역에서 최소 포크·캡 간격 0.714mm, 조인트 하우징·볼 스터드 명목 간격 0.2mm, 최소 전달각 사인 0.781, 최대 모터축 회전 약 50.973°를 확인했다. 실제 하중, 프린트 변형·공차, 장기 토크·온도, 착석 압박 한계는 CAD만으로 확정할 수 없다. 모터 케이스·로드엔드는 참조 형상이므로 실제 부품과의 간섭도 별도로 확인해야 한다. 사용자는 모터 본체만 변경했고 운동축·혼·로드·패드 연결점은 CAD와 동일하다고 확인했다.

프로파일은 `cad_profile_data.py`이며 PC와 STM이 동일 SHA256을 확인한다:
`564128a184182c43c7ff20436298a47e88cdd7c40866a2e6c04dfaa0c043eb36`

## 270° DS5180과 영점

사용자가 직전 180° 답변을 정정하여 네 모터를 **270°**로 확정했다. 변환은 명목 500~2500µs/270°이다. 당시 영점은 UR/UL/DR/DL = 1800/1200/1200/1800µs였으며, 현재 fallback/RL 장착은 2026-10-28 고정 PWM 시험 후 **1800/1800/1200/1200µs**로 확정했다. 270° 제품 표기는 펄스 끝점 실측을 대신하지 않는다. 구조물 Yaw/Pitch와 모터 출력축 각도는 다른 값이다. 180°로 작성됐던 V2와 이전 원시 기록은 이력으로 보존하며 V3 이후의 270° 변환을 유지한다.

배선은 UR=D3, UL=D4, DR=D5, DL=D6. MUX는 D8~D12와 A0/A1/A2를 유지한다.

2026-10-27에 모터 서플라이 OFF 확인 후 270°용 A 펌웨어를 업로드하고 쓰기 후 검증을 통과했다. 실제 ELF 38개 검사 통과 파일과 같은 SHA256(`93aebe1cc503a4bbc488a9d02866d45d774b3a3501e76016d95e3f2c33109c5e`)이며, COM11에서 A v2/270°/CAD 프로파일/튜닝값을 확인했다. 모터 OFF 전용 검사에서 압력 12채널 2,393행·598회 전체 스캔이 오류 없이 수신됐다. 펌웨어 명령 상태·압력 데이터 수신 확인이며 실제 축 위치나 착석 효과 검증은 아니다.

## CubeIDE Live Expressions

수정 대상은 `g_experiment_a_tune`의 각도·속도·응답 파라미터다. 모터 출력을 OFF한 상태에서 값들을 수정하고 `request_seq`를 마지막에 증가시키면 펌웨어가 전체 값을 검증하고 적용한다. 구동 중 변경은 거절한다. 호스트는 다음 연결 때 적용된 STM 값과 revision을 읽어 그 실행에 고정한다. ARM 때 revision이 바뀌었으면 시작하지 않는다.

1. BeamNG Bolster A에서 `중지`하고 STM 출력 OFF를 확인한 뒤 기록의 `저장` 또는 `버리기`를 선택한다.
2. CubeIDE에서 실행을 유지한 채 Live Expressions의 값을 수정한다. Pause/Step을 사용해 조정하지 않는다.
3. `request_seq`를 마지막으로 증가시키고 적용 revision/status를 확인한다.
4. BeamNG Bolster A의 `다시 연결`을 누르거나 프로그램을 다시 실행한다. STM 적용값은 새 세션의 manifest와 화면에 표시된다.

펌웨어 변수 목록·프로젝트·디버그 절차는 `stm32/EXPERIMENT_A_LIVE_TUNING.md`를 참조한다. `g_fallback_debug`는 관측용 복사본이며 값을 바꿔도 모터 제어값으로 사용되지 않는다.

## 실행·기록·업데이트

같은 바탕화면 `BeamNG Bolster A`를 사용한다. 코드 업데이트는 검증된 새 V번호를 만들며, V6 이후 사용자가 명시적으로 저장한 기록만 `바탕화면/BeamNG Bolster A Data/V번호/A_날짜_고유ID/`에 들어간다. 중지·오류·창 닫기만으로 이 최종 경로를 만들지 않는다. 예전 버전과 데이터는 덮어쓰지 않는다.

V7 릴리스 SHA256은 `dbed8c068b6e0cf0bdc6dfcdad82c89082556510c70359595f7e7a896bdfacd1`이다. 기존 시험 설정을 `trial_settings.before_v7_20261027_171011.json`으로 백업했고 장착 확인 5개 값과 펌웨어는 유지했다. 적용 전 V6 창의 저장 완료·출력 OFF·미저장 없음 상태를 확인한 뒤 정상 종료했다. 설치본 UI 검사는 UART/UDP 수집 스레드를 열지 않았으며 새 제어로 실제 모터를 시험하지 않았다. 검증 후 앱은 닫아 두었고 다음에 같은 아이콘을 실행하면 V7이 열린다. V7 소스는 `BeamNG_Bolster_FB`의 V6 기준 커밋 `6bcf848`을 잇는다. V6 이력과 설치 릴리스는 보존하며, Git 병합은 다른 PC의 설치본 또는 보드 펌웨어를 자동으로 변경하지 않는다.

### V6 배포·화면 검증 이력

배포한 V6 릴리스 SHA256은 `d46e69f4b816bbf6543d8474f6a3c8fd4606c31da0d8fe7654dbf3065da4ee4a`다. 호스트 238개 검사(19.081초), 설치본 `--check-ui` 및 `git diff --check`를 통과했다. 기존 프로필·시험 설정은 `before_v6_20261027_151154.json` 백업을 남겼고 장착 확인값은 유지했다. 펌웨어는 이번 호스트 업데이트에서 바꾸지 않았다.

게임에서 순정 Vivace 160 DCT를 선택하고 로그의 구성 경로·차량 ID 41332 및 Vehicle 패널의 `BeamNGOfficial` 출처를 확인했다. 사용자 정의 기본 차량 저장은 취소했으며 현재 순정 차량 선택을 유지한다. V6 창과 하단 고정 `중지/저장/버리기/다시 연결` 버튼이 화면 안에 표시되는 것도 확인했다.

V6 배포 직후 앱은 **OFF·미저장 기록 1개** 상태였다. `pending_sessions/V6/A_20261027_151342_ee6cafb8`는 차량 518행·압력 19,551회 전체 스캔을 남겼으며 게임 메뉴 전환 중 200ms 입력 공백으로 종료해 OFF를 확인했다. 이 화면 검증에서는 잠시 중립 0° 연결까지만 확인했고 임시 기록의 저장/버리기는 사용자 선택으로 남겼다. 이는 과거 점검 시점이며 현재 세션 수나 보존 상태를 뜻하지 않는다.

V6는 종료/오류 후 임시 기록의 저장 또는 버리기 선택을 마친 뒤 `다시 연결`로 새 임시 세션을 만든다. 정상 BeamNG 데이터가 2초 이상 들어오면 해당 세션에서 한 번 자동 시작하며 오류 후 저절로 재ARM하지 않는다. 직전 V5 릴리스와 측정은 원래 위치에 보존한다.

V4의 실제 세션은 14:35:09.829 KST에 CONTROL에 진입했으나 14:35:21.337에 차량 샘플이 200.1201ms 동안 끊겨 OFF로 종료했다. V5는 이 상태를 “연결 대기”로 표시하지 않고 중단 이유와 확인된 최종 OFF·압력 통계를 표시한다. 전체화면 복귀 중 UDP 수신 공백 0.618882초가 별도 진단에서 재현되어 게임 표시 모드를 Borderless로 바꿨다. 백그라운드 30FPS 설정은 유지했다. 변경 후 실시간 검증은 진행 중이며 지속 운전 안정성을 아직 확정하지 않는다.

메뉴 일시정지·차량 로딩·렌더링 정지로 차량 입력이 200ms 넘게 끊기면 OFF로 종료한다. 이 제한을 늘리거나 오래된 차량 값을 새 데이터처럼 반복 전송하지 않는다. 재개 전 게임에서 차량이 로드되고 일시정지가 해제되어야 한다.

새 통합 펌웨어는 `OASIS_FALLBACK v2`, **270° 변환**, CAD 프로파일, STM 튜닝 revision이 모두 맞아야 한다. 잘못 지정됐던 180° 이미지, 기존 수집용 `OASIS_CONTROL v6`나 fallback v1은 시작하지 않는다. 코드 설치가 보드 펌웨어 업로드를 수행하지는 않는다.

신호의 stale·역순·유실, UART 오류, 기록 실패 또는 장치 오류 시 OFF로 고정하고 자동 재ARM하지 않는다. STATE/PWM은 명령 상태이며 실제 축·토크 측정값이 아니다. 전원을 끈 뒤 기구가 움직이지 않는다는 보장도 아니다.

`--preview`는 장치·네트워크를 열지 않는 설정/안내 화면이다. 실제 실행 전 확인값은 새 설정에서 false로 시작하며 실물 확인을 대신 작성하지 않는다.

## 주요 통합 사례

1. **자동 시작:** 차량 수집기 소켓/파일 준비 전에는 포트를 열지 않는다. USB가 없으면 대기하고, 연결 후 유효 차량 입력2초와 보드 OFF를 확인해 한 번 ARM한다. 모의31초 게임 대기에서도 타임아웃 없이 압력 스캔/독립 PING을 유지하고 이후 시작했다.
2. **제어 입력 분리:** 낮은/높은 압력, 손상되거나 누락된 압력 행에서 같은 차량 입력에 동일 모터 명령이 나오는 것을 실제 A 제어기로 확인했다. 압력은 controller.tick 인자에 없다. 명시적 보드/UART 고장과 기록 실패는 별도로 종료한다.
3. **압력 보존:** 각 원시 행의 ADC/status/MCU tick/sequence/호스트 시각과12채널 스캔을 JSONL·CSV에 보존한다. 원문 파싱 오류·시퀀스 누락·큐 드롭·미완성 스캔을 품질 이벤트로 기록한다. 이전의 최신 스캔 하나만 읽는 경로를 재사용해 행을 버리지 않는다.
4. **저장 안정성:** 쓰기/fsync는 유한 큐의 별도 스레드에서 수행한다. 큐 초과·디스크 오류·종료 시간 초과를 감지하고 `INCOMPLETE`를 유지한다. 오류 로그를 남기다 다시 실패해도 모터 OFF 정리 경로를 건너뛰지 않는다.
5. **시간 경쟁:** UART 처리 중 수집기가 만든 새 차량 행을 루프 시작 시각과 비교해 `future_timestamp`로 오인하던 가능성을 제거했다. 수신 뒤 현재 시각을 다시 읽는 회귀 검사를 추가했다. 수신 도중 중지 요청이 들어오면 같은 반복에서 ARM/lease/SET을 보내지 않는 것도 검사했다.
6. **종료:** 사용자 중지·원본 수집기 종료·제어 오류는 공통 stop으로 전달한다. fresh PWM OFF와 압력 DISABLE ACK를 따로 확인한다. 창 닫기는 수집기 저장 완료를 기다린다. 반환·예외·통신 복구 후 자동 재ARM/재시작하지 않는다.
7. **실행 설치:** 기존 BeamNG Data Collector 바로가기와 설치 코드·모드·설정은 보존한다. 새 실행 프로필만 `%LOCALAPPDATA%/OASIS/ExperimentA`에 설치하고, 최초 장착 확인값5개는 모두 false로 유지했다.

테스트 UART/UDP/clock/장착 확인값은 메모리 또는 임시 폴더의 fixture다. 실제 포트를 열거나 네트워크에 bind하거나 펌웨어를 올리거나 모터를 구동하지 않았다. 실물100Hz 수집 유지율, USB/모터 부하 지연, 저장장치 지연, 착좌 압력과 지원 효과는 이후 장치 시험에서 확인한다. 기록 전압은 힘/Pa 교정값이 아니다.

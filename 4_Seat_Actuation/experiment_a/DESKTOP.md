# BeamNG Bolster A — 자동 제어·충격 후 기록 유지·선택 저장

2026-10-27 배포한 V7 기준 사용 안내다. 최종 호스트 검사 273개(14.867초), `git diff --check`와 설치본 `--check-ui`를 통과했다. 같은 바탕화면 바로가기와 실행기를 사용하며 이전 버전·측정·설정 백업은 보존한다. 충격 의심 판정의 실제 충돌 검출 성능과 착석 압박 효과는 아직 검증하지 않았다.

설치본 UI 검사는 UART/UDP 수집 스레드를 열지 않았다. 적용 전 저장 완료·출력 OFF 상태의 V6 창을 정상 종료했고 검증 후 앱은 닫아 두었다. 다음에 같은 `BeamNG Bolster A` 아이콘을 실행하면 V7이 열린다. 기존 시험 설정은 `trial_settings.before_v7_20261027_171011.json`으로 백업했으며 장착 확인값 5개와 펌웨어는 유지했다. 릴리스 해시는 [실험 A 설명](README.md)에 있다. V7을 실제 모터에 연결해 시험한 결과는 아니다.

V6 배포 직후의 238개 검사·화면 확인과 미저장 기록 1개는 과거 점검 이력이다. 이후 사용자가 비충돌로 확인한 `A_20261027_165300_984bb9af`에서도 한 샘플의 횡가속도 12.871m/s²로 종료돼 V7의 판정 분리를 진행했다. 현재 기록의 보존 상태는 앱 또는 `recording.json`에서 확인한다.

바탕화면 `BeamNG Bolster A.lnk`를 실행하면 STM USB와 BeamNG 데이터를 기다린다. 차량 수집기가 원본 파일을 열고, 보드 통합 펌웨어·PWM OFF를 확인하고, 유효 차량 입력이 2초간 이어지면 한 번 자동으로 중립 신호를 출력한 뒤 A 제어를 시작한다. 정지 차량에서는 중립을 유지하고 주행 횡가속도에 따라 움직인다. 게임 로딩 대기에는 시간 제한이 없다.

처음 한 번은 예정된 하드웨어 디버깅에서 **CAD 제한을 포함한 실험 A용 펌웨어 업로드 및 장치 설정**이 필요하다. 창의 `장치·설정 확인`에서 CAD 운동축/링크·배선·영점/Pitch 방향·체결·중립 간섭·시험 설정을 실제로 확인하여 저장하면 이후 실행부터 별도의 ARM 버튼 없이 기다렸다가 시작한다. 프로그램은 확인값을 임의로 true로 바꾸거나 펌웨어를 자동 업로드하지 않는다. 일반 데이터 수집용 펌웨어와 실험 A용 펌웨어는 서로 다른 프로토콜이다.

PWM-서보 출력축 각도는 현재 500~2500µs에 270°로 대응시킨 가정이다. 제품의 실제 180°/270° 범위와 혼 영점이 다르면 CAD에서 계산한 구조물 각도도 달라지므로 장치 확인 항목에 이 보정을 포함한다. 명령 상태 표만으로 이 보정이 맞는지 확인할 수는 없다.

## STM 상태와 Live Expressions 조정

2026-10-27 개정 창에는 좌·우 볼스터의 최근 명령 Yaw/Pitch와 목표 Yaw/Pitch, UR/UL/DR/DL PWM, 마지막 응답 이후 경과시간이 표시된다. 이 값은 STM이 보고한 **명령 상태**이며 실제 서보 출력축 각도·전류·토크·접촉하중을 측정한 값이 아니다. 연결 전에는 임의의 0° 대신 `—`로 표시한다.

앱의 `STM Live Expressions 적용값` 표는 아래 여섯 항목과 STM 적용 revision을 읽기 전용으로 보여준다. 연결 전에는 로컬 설정을 실제 적용값처럼 표시하지 않는다. 값 수정은 STM32CubeIDE의 `g_experiment_a_tune`에서 한다.

| 항목 | 의미 |
|---|---|
| Yaw 상한 | 볼스터 구조물의 최대 닫힘 각도 |
| Pitch 상한 | Yaw별 CAD 허용치와 함께 적용되는 추가 상한 |
| Yaw / Pitch 속도 | 호스트 목표 변화율; 별도의 PWM 변화율 제한도 유지 |
| 최대 반응 횡가속도 | 해당 횡가속도 크기에서 설정한 최대 반응에 도달하는 기준값 |
| Pitch 응답 배율 | BeamNG 가속도의 등가 기울기 신호에 적용하는 배율; 체형 보정값이 아님 |

앱에서 `중지`하여 STM 출력 OFF를 확인하고 기록의 `저장` 또는 `버리기`를 선택한다. CubeIDE에서 실행을 유지한 채 여섯 값을 수정하고 `request_seq`를 마지막에 증가시킨다. `applied_seq`와 결과를 확인한 뒤 앱의 `다시 연결` 또는 재실행으로 새 세션을 시작한다. 구동 중 변경은 거절되며, 호스트는 연결 때 읽은 STM 설정을 그 세션에 고정한다. 전체 유효 설정과 revision은 manifest에 기록한다. 변수명과 상세 절차는 [Live Expressions 안내](../stm32/EXPERIMENT_A_LIVE_TUNING.md)를 따른다.

장치 없이 화면을 확인하려면 다음 명령을 사용한다. `--preview`는 읽기 전용 안내 화면이며 UART·UDP·수집 스레드를 열거나 설정을 바꾸지 않는다. `--check-ui`도 장치를 열지 않는 숨긴 생성 검사다.

```powershell
python "$env:LOCALAPPDATA\OASIS\ExperimentA\bootstrap.py" --profile "$env:LOCALAPPDATA\OASIS\ExperimentA\desktop_profile.json" --preview
```

## 사용 순서

1. 최초 장착 확인을 마친 뒤 `BeamNG Bolster A`를 실행한다. 이전의 미저장 임시 기록이 있으면 먼저 복구 목록에서 저장 또는 버리기를 선택한다. 미해결 임시 기록이 있는 동안 자동 시작·재연결은 차단된다. 전용 통합 펌웨어의 보드 USB가 있으면 자동 선택하고, 없으면 연결을 기다린다. ST-LINK가 여러 개이면 실행 프로필의 `port`를 지정한다. Bluetooth나 다른 USB 직렬 장치를 임의 선택하지 않는다.
2. BeamNG에 차량을 불러온다. 기존 v0.3 모드가 데이터를 보내면 원본 저장과 유효성 확인이 시작된다. 기존 모드가 설치돼 있으면 다시 설치할 필요가 없다.
3. 연결이 안정되면 모터 제어가 자동 시작된다. 압력 스캔은 보드 연결 시 시작되어 구동 전과 구동 중 값을 모두 남긴다. 제어 시작 때 짧은 알림음을 낸다.
4. V7의 충격 의심 조건이 성립하면 **모터만 OFF하고 같은 세션의 차량·압력 기록은 계속**한다. 화면은 OFF 확인 중인 `IMPACT_OFF_PENDING`과 확인된 `RECORD_ONLY`를 구분한다. 이 세션에서 자동 재구동하지 않는다. 기록 중에는 저장/버리기를 할 수 없다.
5. 기록을 끝내려면 `중지`를 누른다. 모터 `FB_OFF`, 압력 `DISABLE`, 기록 스레드 종료를 기다린다. 중지는 영구 저장을 뜻하지 않는다. 통신·장치·기록 오류와 OFF 확인 실패는 전체 실행을 종료한다. 구동 중 200ms 입력 공백·잘못된 시각/스트림/파생값 등의 검사는 유지한다.
6. 종료한 임시 기록의 `저장` 또는 `버리기`를 선택한다. 저장은 그 기록만 최종 데이터 폴더로 옮기며 버리기는 선택한 임시 기록만 삭제한다. 모든 미저장 기록을 처리한 뒤 `다시 연결`을 누르면 새 임시 세션으로 연결하고, 유효 차량 데이터 2초 후 한 번 자동 시작한다.

창 닫기는 실행을 중지하고 임시 기록을 남긴다. 자동 저장·자동 삭제하지 않는다. 다음 실행의 `미저장 기록` 목록에서 처리할 수 있다. 충격 의심 표시는 확정 충돌 판정이 아니다. 유효한 큰 횡가속도에서는 기존 최대 목표·기구/속도 제한을 유지한다. 별도 충격 판정은 수평 합성가속도 25m/s² 이상·급변 150m/s³ 이상·연속 0.06초·구간 적분 1.5m/s를 모두 요구하며, 합성 60m/s² 이상은 즉시 모터 OFF한다. 상세 조건과 한계는 [RUNTIME.md](RUNTIME.md)에 있다.

기존 `BeamNG Data Collector` 바로가기는 그대로다. 새 프로그램과 기존 수집기는 같은 UDP64256을 사용하므로 동시에 실행하지 않는다. 새 프로그램은 단일 인스턴스로 동작하며 수집기의 소켓/파일 준비가 실패하면 모터 포트를 열지 않는다. 사용자 중지 후 PWM OFF는 외부 서플라이 차단이나 기구 위치 유지/압박 해제를 뜻하지 않는다.

## 저장 위치와 파일

수집 대기를 시작하면 `%LOCALAPPDATA%/OASIS/ExperimentA/pending_sessions/V번호/A_날짜_시각_고유ID/`에 임시 기록을 만든다. 실제 디스크를 사용하므로 창을 닫거나 프로세스가 비정상 종료돼도 복구할 수 있다. 중지나 오류만으로 바탕화면의 최종 기록 폴더를 만들지는 않는다.

사용자가 **저장**을 선택한 기록의 기본 최종 위치는 바탕화면 **BeamNG Bolster A Data**다. 창에 표시된 `V번호/A_날짜_시각_고유ID`처럼 코드 버전 아래 실행별 폴더로 옮긴다. 같은 초에 여러 번 실행해도 고유 ID가 달라 덮어쓰지 않는다. `기록 폴더 열기`는 현재 임시 또는 저장된 기록 위치를 연다.

```text
BeamNG Bolster A Data/
  V1/
    A_YYYYMMDD_HHMMSS_xxxxxxxx/
  V2/                             # 코드 업데이트 후 별도 버전
    A_YYYYMMDD_HHMMSS_xxxxxxxx/
```

각 실행 폴더 내부:

```text
A_YYYYMMDD_HHMMSS_xxxxxxxx/
  recording.json                  # 임시/저장 상태·원래 경로·소유 기록 ID
  recording_relocation.json       # 저장 선택 시 생성: 임시 경로 → 저장 경로
  experiment.json                 # V번호·코드 해시·설정·라벨·시작/종료·수집기 경로
  beamng/sessions/날짜/session_.../
    raw/telemetry.jsonl            # 기존 수집기 원본 패킷
    vehicle/vehicle.csv            # 속도·종/횡가속도·조향·페달 등
    imu/imu.csv, obd/obd.csv       # 기존 수집기의 파생 기록
    metadata.json, session_summary.json
  control/
    control.jsonl                 # 입력 프레임·제어 진단·목표·보드 명령 상태
    pressure.jsonl                # 압력 원문·파싱·전체 스캔·품질 이벤트
    pressure_raw.csv              # 각 채널 그룹의 raw ADC/status/시각
    pressure_sweeps.csv            # 완성된 12채널 스캔 + 채널별 시각
    manifest.json                 # 제어/관측 구분·설정·해시·OFF 확인·수집 통계
    INCOMPLETE                    # 정상 실행 종료 시 제거, 오류/미완료 시 유지
```

저장 시 원본 CSV/JSONL 및 기존 manifest의 바이트는 수정하지 않는다. 따라서 내부에 기록된 과거 절대 경로는 임시 폴더를 가리킬 수 있다. `recording_relocation.json`과 `experiment_a.recording_lifecycle.resolve_recording_path()`로 현재 기록 폴더 안의 경로로 해석한다. `experiment.json`의 `recording_retention_at_capture=pending`은 수집 당시 상태이며 현재 보존 상태는 `recording.json`을 확인한다. `저장`은 오류 기록을 정상 데이터로 바꾸지 않으며 기존 `INCOMPLETE`도 그대로 보존한다.

압력은 명목 채널당100Hz이며 세 뱅크의 같은 채널을 한 행에 보내므로 원시 행은 약400행/초, 완성 스캔은 약100개/초다. 원시 ADC와 상태코드를 보존하고 명목 전압은 `ADC × 3.3 / 4095`로 기록한다. 힘이나 Pa로 교정된 데이터가 아니다. 센서 매핑은 A0=좌판, A1=사이드, A2=등판이며 A1 C0/C1/C2/C3=DR/UR/DL/UL이다.

차량·압력·제어의 `host_monotonic_ns`는 동일 PC의 `perf_counter_ns` 시간축이다. 차량 원래 수신시각, simulation time, stream/vehicle/sequence ID와 압력 MCU `t_ms`·sequence를 따로 보존한다. 12채널은 동시에 샘플링되지 않으며 압력 호스트 시각에는 UART 전송 지연이 포함된다. 서로 다른 시계를 숫자만 보고 직접 결합하지 않는다.

압력 원문·품질·드롭 수를 남겨 누락을 정상 측정처럼 숨기지 않는다. 압력값·기준선·접촉 여부는 A 제어기 인자가 아니며 정상 범위의 압력값이 달라도 같은 차량 입력에는 같은 모터 명령이 나온다. 모터와 압력은 한 UART 소유자가 처리하지만 `FB_PING`과 압력 `PING`의 lease는 독립이다. 명시적 보드 고장·통신 오류는 종료하며 압력 자료 품질 문제는 기록한다. 로그 큐 초과·디스크 오류는 실험을 종료하고 미완료 표시를 남긴다.

## 설정과 설치

PC 전용 실행 프로필은 `%LOCALAPPDATA%\OASIS\ExperimentA\desktop_profile.json`, 시험 설정은 같은 폴더의 `trial_settings.json`이다. 현재 후보 수치와 CAD 제한 근거는 `config.candidate.json` 및 [실험 A 설명](README.md)에 있다. 이번 개정 제어는 참가자의 키·체중에 따른 보정을 사용하지 않는다. 실제 실행한 설정은 각 실험 manifest에 복사한다. 코드의 후보 JSON을 수정해도 일반 업데이트에서는 이미 설치된 시험 설정을 자동 덮어쓰지 않는다.

실행 프로필의 `labels`에 참가자·시나리오·반복 실험 이름을 둘 수 있다. 라벨은 기록 구분용이며 제어 보정 입력이 아니다. 구체적인 차량·시나리오 설정은 기존 수집기의 metadata도 함께 보존된다. A/C 비교 시 같은 시나리오·참가자·기구·각도/속도·평가 구간을 사용하고 실제 압력·자세의 지표로 비교한다. 제어기의 가속도 등가 기울기는 효과 평가용 실측 자세가 아니다.

재설치는 `4_Seat_Actuation`에서 실행한다. 기존 개인 설정은 보존한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File experiment_a/Install_Desktop.ps1 -PythonPath <venv>/Scripts/python.exe -CollectorRoot <BeamNG_Collector_v0_3>
python "$env:LOCALAPPDATA\OASIS\ExperimentA\bootstrap.py" --profile "$env:LOCALAPPDATA\OASIS\ExperimentA\desktop_profile.json"
```

2026-10-27처럼 사용자가 기준 재설정을 요청한 개정에서는 `Install_Desktop.ps1 -ResetSettings`를 **명시적으로** 사용할 수 있다. 기존 설정과 프로필을 `*.before_reset_날짜_고유ID.json`으로 먼저 보존하고, 새 후보 설정 및 미확인 장착값으로 바꾼다. 개인 체격 라벨은 `unpersonalized`로 바꾸며 원래 라벨은 백업과 기존 측정에 남는다. 새 release 게시에 실패하면 기존 시험 설정을 복원한다. 이 옵션은 일반 업데이트에서 자동으로 사용하지 않는다.

보드 통합 이미지는 `stm32/build_fallback/fallback_control_h723.elf/.bin`이다. 압력 전용 이미지와 구분한다. 기존 270° A v2 통합 펌웨어의 업로드 이력과 V6 릴리스 해시는 [실험 A 설명](README.md)에 있다. V7은 호스트 수정이며 이번 업데이트에 펌웨어 재업로드는 필요하지 않다. 실제 충격 판정·착석 압박 반응 검증은 남아 있다.

## 같은 프로그램의 V1 → V2 → V3 업데이트

바탕화면 이름과 바로가기는 계속 **BeamNG Bolster A**를 사용한다. 바로가기는 고정 실행기 `bootstrap.py`를 열고, 실행기는 선택된 버전의 코드 해시를 검증한 뒤 그 사본을 실행한다. 프로젝트 소스를 수정해도 이미 설치된 V1 사본은 변하지 않는다.

1. 코드를 수정·검증한다. 개발 원본 경로는 실행 프로필의 `source_root`다.
2. 프로그램의 `중지`와 기록의 `저장`/`버리기` 선택을 마친 뒤 **업데이트**를 누른다. 최초 장치 확인 대기 상태에서도 업데이트할 수 있다. 구동 중에는 버튼이 비활성화된다.
3. 실행 코드가 달라졌으면 V2, 다음 변경은 V3처럼 새 사본을 만든다. 코드가 같으면 현재 버전을 재사용한다. 복사·Python 구문·해시 검증에 성공한 후 활성 버전을 바꾼다.
4. 창을 닫고 **동일한 바탕화면 바로가기**를 다시 실행한다. 새 버전 이름이 창에 표시되고 저장을 선택한 기록만 해당 버전 폴더에 보존된다. 실행 도중 코드를 교체하거나 모터를 자동 재시작하지 않는다.

이 업데이트는 PC의 수정된 프로젝트 코드를 설치하는 기능이며 인터넷/Git 원격 변경을 자동으로 내려받지 않는다. 설치 스크립트를 다시 실행해도 같은 게시 경로를 사용한다. 다른 프로그램 창이 실행 중이면 외부 설치는 잠금으로 거절한다.

코드 사본은 `%LOCALAPPDATA%/OASIS/ExperimentA/releases/V1`, `V2`…에 보관한다. 각 `release.json`은 실행 모듈·공유 의존성·기본 설정의 파일별 해시와 전체 해시를 기록하고, `current.json`은 다음 실행 버전을 선택한다. 문서·테스트·캐시만 바뀌면 V번호를 올리지 않는다. 기존 무버전 데이터는 원래 위치에 남겨두며 근거 없이 V1 기록으로 옮기지 않는다.

시험 설정과 장착 확인값은 업데이트 시 그대로 유지한다. 새 코드의 기본 설정 파일이 달라졌어도 기존 시험 설정을 자동으로 덮어쓰지 않고 안내한다. 실행마다 실제 사용한 설정 전체와 코드 버전·해시를 `experiment.json` 및 `control/manifest.json`의 session metadata에 남긴다. 설정만 수동 조정하면 V번호는 그대로이며 기록된 설정으로 구분할 수 있다. 개발용 저장소 코드를 직접 `-m experiment_a.desktop`으로 실행하면 `DEV`로 표시·분리되므로 일반 실험에는 설치된 바로가기를 사용한다.
